# Сравнение моделей на Dart

Инструмент M1 обращается только к локальному HTTP API Ollama. Он не является кодом будущего интерфейса приложения.

## Запуск

Из папки `tools/model_benchmark`:

```powershell
dart pub get --enforce-lockfile
dart run bin/benchmark.dart --model qwen3.5:4b --data ../../benchmarks/cases-v1.jsonl --prompt ../../benchmarks/prompt-v1.txt --split test --output ../../benchmarks/results/qwen-test.jsonl
```

Ollama должен быть запущен, а модель — уже скачана. Перед прогоном инструмент выгружает находящиеся в памяти модели, поэтому для сравнения следует использовать отдельный экземпляр Ollama без других активных задач.

Параметры:

- `--model`, `--data`, `--prompt`, `--output` — обязательны.
- `--split dev` или `--split test` — часть набора; по умолчанию `test`.
- `--limit 3` — ограничить число примеров для проверки совместимости или измерения CPU.
- `--cpu` — запросить `num_gpu=0`; фактическое размещение проверять по записи `resident_memory`.
- `--endpoint` — локальный адрес Ollama; по умолчанию `http://127.0.0.1:11434`.

Существующий файл результата не перезаписывается. JSONL пополняется после каждого примера; полный прогон заканчивается записью `summary`. Незавершённый файл не считается завершённым измерением.

## Что измеряется

В файл записываются версия Ollama, сведения о модели, шаблон диалога, инструкция, схема JSON и параметры. Первый запрос (`cold_start`) измеряется отдельно и не входит в статистику повторной проверки. Затем первый пример повторяется как часть общего прогона: общий системный контекст может использовать кеш Ollama, как и при последовательной работе приложения.

Каждая замена должна иметь существующий однозначный исходный фрагмент. Пересечения, дубликаты, отсутствующие фрагменты и замены без изменений отклоняются. Разная ширина правильного контекста и разбиение общей правки на несколько допустимых замен не должны ухудшать оценку.

- `precision` — доля принятых механизмом проверки предложений, которые меняют только ожидаемые части текста.
- `raw_precision` — тот же показатель с дополнительным штрафом за отклонённые предложения модели.
- `recall` — доля полностью выполненных эталонных исправлений. Составная эталонная правка требует всех её изменений.
- `false_notice_rate` — доля правильных текстов, для которых модель предложила хотя бы одну замену, включая отклонённую. В отчёте отдельно считается доля замечаний, оставшихся после проверки фрагментов.
- `exact_rate` — доля полностью правильных итоговых текстов без отклонённых предложений и ошибок структуры.
- `schema_valid_rate` — доля ответов с правильной структурой. Она не подтверждает языковое качество.
- `median_seconds`, `p95_seconds` — время локального HTTP-запроса и чтения ответа; оценивание и запись файла происходят после остановки таймера.

Точность предложений и полнота эталонных исправлений используют разные единицы счёта: модель может разделить одну эталонную правку на две допустимые подсказки. Числа `correct_predictions` и `tp` поэтому могут различаться.

Строгие эталоны не охватывают все возможные правильные формулировки. Неожиданные ответы нужно разбирать вручную. После использования этого набора для выбора модели дальнейшая независимая приёмка требует новых текстов.

## Проверка инструмента

```powershell
dart format --output=none --set-exit-if-changed .
dart analyze --fatal-infos
dart test
```

Автоматические тесты проверяют сравнение эффектов замен, Unicode, неоднозначные фрагменты, пересечения, структуру ответов и целостность набора. Модели в CI не скачиваются.
