# Выбор исправлений по ролям источников

Используются все прежние компоненты: общий словарь OpenCorpora OR Hunspell, SymSpell на Dart, Hunspell с расстоянием/частотами, локальный LanguageTool 6.8 и GigaChat 20B Q4_K_M. [Итоговая независимая проверка](../results/2026-11-04/ensemble-tuning/README.md).

## Что изменилось

Пул предложений `ensemble-v1` и его защита не изменены. Новый `src/ensemble_roles.dart` выбирает из **тех же вариантов**, опираясь на признаки без эталонов: известность слова, источники, близость замены, тип правила LT и контекст. Произвольный ответ модели не вставляется в документ.

1. Контекстное предложение GigaChat получает предпочтение среди орфографических альтернатив. Это устраняет выбор первого, но неподходящего слова вроде «хотеть» вместо «хочет».
2. Более близкий вариант, согласованный LT/Hunspell/SymSpell, может сохранить авторскую форму лучше модели. Для эквивалентных готовых вариантов по е/ё предпочтение получает сохранение существующей ё.
3. Стилистические рекомендации отделяются по описанию правила LT. Категория STYLE сама по себе не запрещена: у LT туда попадает и управление после предлога.
4. Неоднозначная смена числа при количественном подлежащем и некоторые неизвестные слова после указания имени остаются на просмотр. Это эвристики, не полноценный морфологический анализ или распознавание всех имён.
5. Модельная запятая без другого источника допускается лишь в ограниченных конструкциях с придаточным или сопоставлением. Необязательная пунктуация остаётся среди альтернатив. Пунктуационная замена из непунктуационного правила LT не получает автоматического преимущества.
6. Без контекстного предложения модели однозначное совпадение трёх орфографических каналов либо первое конкретное правило GRAMMAR может дать рекомендацию. Согласие каналов не является статистической гарантией: они используют связанные словарные данные.

Для выбора неподдержанного контекстного изменения близкой формы слова требуются известные исходник/замена, общий префикс и малое расстояние. Это намеренно ограниченная эвристика; она может пропускать ошибки и не доказывает правильность любой похожей формы.

## Разработка и приёмка

Все прежние **448 текстов**, включая старые fresh48, считаются материалом разработки. Сравнены семь схем: LT, прежний приоритет, контекстное предпочтение, строгое согласие, добавление придаточных, добавление близких форм и компактный закрытый выбор GigaChat. Правило выбора — `selection-rule.json`: нулевое изменение правильных текстов/защищённых фрагментов, точность отдельных эффектов не ниже 95%, затем максимальное число чистых исправлений. При недостижении порогов предусмотрен явный запасной порядок; он не понадобился.

Компактный GigaChat — отдельный фиксированный запрос с явными id и максимумом рекомендаций источников вместо длинных списков. Одновременно изменены представление и инструкция, поэтому улучшение нельзя приписать одному из них. Он не выбран для рабочего режима.

Для выбранного профиля дополнительно исключались по одному четыре канала предложений (`ablation-rule.json`). Общий словарь распознавания при этом сохранялся. Ни один вариант без канала не доминировал полный, поэтому все источники оставлены. Это не доказательство оптимальности среди всех возможных алгоритмов.

**140 новых текстов / 60 ошибочных и 80 правильных** зафиксированы в `0f39419` до выбора профиля. После разработки код, решение, данные и параметры заморожены `freeze.py`, коммит `8f426c3`. На новом наборе проверяется только выбранный профиль и две исходные схемы. После получения оценки алгоритм не меняется и другой победитель по новым данным не выбирается.

## Рабочая команда

Из `tools/model_benchmark`, с уже подготовленными словарями и работающими локальными LT/Ollama:

```powershell
dart run bin/ensemble_review.dart --text-file E:/korrekta/my-text.txt --output work/review.json
dart run bin/ensemble_review.dart --text-file E:/korrekta/my-text.txt --names E:/korrekta/my-names.json --output work/review-with-names.json
```

`proposed_text` содержит рекомендации выбранного профиля `inflections`. `all_sources_proposed_text` сохраняет прежнее широкое объединение для сравнения; оно может содержать ложные правки. `details.slots` содержит все альтернативы и источники, `recommended_choices` — номера рекомендаций, `deferred_slots` — фрагменты, оставленные на просмотр. Они не удаляются из списка и не объявляются правильными. Исходный файл не перезаписывается, `automatic_application:false` сохраняется. Сбой источника обозначается как неполная проверка.

Публичное ядро `lib/ensemble.dart` экспортирует `roleFeatures` и `chooseRoles`; Flutter-интерфейс ещё не подключён. Личный словарь задаёт человек. Вход новой политики — снимок, варианты и признаки, без expected/protected/category; есть тест невлияния эталонной разметки. Выбранные номера применяются прежней проверкой UTF-16 диапазонов и снимка.

## Проверка артефактов

```powershell
python -X utf8 benchmarks/ensemble-tuning/freeze.py --check
python -X utf8 benchmarks/ensemble-tuning/evaluate.py --phase dev --check
python -X utf8 benchmarks/ensemble-tuning/ablate.py --check
python -X utf8 benchmarks/ensemble-tuning/evaluate.py --phase fresh --check
python -X utf8 benchmarks/ensemble-tuning/audit.py
```

Эти команды проверяют сохранённые результаты без моделей, E: и сторонних Python-пакетов. Первичный расчёт метрик использует прежний Dart `compare_texts.dart`. При подготовке признаков `ensemble_roles.dart --features` нужны словари на E:, но генерация модели и HTTP LT повторно не выполняются. Для свежего сбора используется прежний `ensemble_check.dart --collect-only`, затем подготовка признаков и `ensemble_roles.dart --profile inflections`.

Новых весов или зависимостей нет. Для новых 140 текстов все ответы GigaChat и LT получены заново, без повторного использования старых генераций. Контекст 8192, temperature 0, seed 42; официальный двухсообщенческий raw-шаблон прежний. Второй модельный отбор не нужен рабочему профилю. Ограничения исходного пула (1200 символов, 32 группы, ограничение вариантов, защита оформления и отдельная команда раскладки) остаются в силе. Качество и реальную задержку всего Flutter-приложения ещё предстоит проверять отдельно.
