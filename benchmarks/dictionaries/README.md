# OpenCorpora + SymSpell на Dart и Hunspell

Сравнение локальной словарной орфографии и отдельного режима раскладки. Интерфейс Flutter не подключается. Проверка текста, выбор замен, защита и оценка реализованы на Dart; Python только подготавливает данные и организует исследование. Эталонный Hunspell — настоящий отдельный нативный процесс, а не упрощённое чтение его `.dic`.

## Данные и версии

- OpenCorpora: снимок из `pymorphy3-dicts-ru 2.4.417150.4580142`, источник `opencorpora.org`, ревизия 417150, формат 0.92, сборка **8 января 2022**. Прямой экспорт OpenCorpora при подготовке возвращал 403/404; использован версионированный подготовленный снимок, не заявляется актуальный словарь 2026 года. Из `words.dawg` извлечено **3 017 654** уникальных написания после нормализации ё→е. Морфологические теги не используются для разбора контекста или отбрасывания помет: наличие записи не равнозначно нормативности во всех регистрах речи.
- Частоты: `SymSpell.FrequencyDictionary/ru-100k.txt` пересечён с формами OpenCorpora — **99 193** кандидата. Английский `en-80k.txt` — **79 851** написание для проверки обратной раскладки. Данные и ревизия Git закреплены в [data-manifest.json](data-manifest.json).
- Hunspell **1.7.5**, пакет MSYS2 UCRT64 `1.7.5-2` и его необходимые DLL с официальными SHA-256. Изолированно распакован на E:, без установки MSYS2, компилятора, служб или изменения PATH. Русский и английский словари LibreOffice закреплены ревизией из манифеста. Оба настоящих `.aff` применяются движком.
- DAWG-Python 0.7.2 использован только как просмотренный декодер при подготовке. Оба wheel получены с PyPI и сверены с опубликованными SHA-256. В системный Python пакеты не устанавливались; они не нужны во время проверки на Dart.

Источники: [OpenCorpora](https://opencorpora.org/?page=downloads), [подготовленные словари](https://github.com/no-plagiarism/pymorphy3-dicts), [SymSpell](https://github.com/wolfgarbe/SymSpell), [сборка MSYS2](https://packages.msys2.org/packages/mingw-w64-ucrt-x86_64-hunspell), [русские файлы LibreOffice](https://github.com/LibreOffice/dictionaries/blob/master/Dictionary_ru.mk). Условия данных и лицензии движков различаются; исходные уведомления сохранены рядом с локальными словарями/в пакетах, перед будущей упаковкой приложения потребуется учитывать их отдельно.

## Фиксированная политика

`symspell.dart` реализует симметричные удаления префикса длиной 7, максимум 2 удаления и точную проверку расстояния OSA с соседней перестановкой за одну операцию. Выбор: минимальное расстояние, максимальная частота, затем лексикографический порядок. Это собственная реализация алгоритма на Dart, не запуск оригинального C# и не утверждение об идентичности всей библиотеки SymSpell. Работоспособность вставок, удалений, перестановок, длинных слов и ранжирования проверена тестами.

Известные словарю слова не переписываются. Неизвестное русское слово длиной 3–32 может получить небольшую замену: не более 2 операций и 40% длины. Существующая ё не удаляется, включая составную замену с исправлением другой буквы. Поисковая нормализация ё/е не меняет исходный текст. Грамматика, пунктуация, смысл, стилистика, вставка/удаление слов и разделение слов не реализованы. Дефисные слова пропускаются целиком.

Hunspell проверяется в двух вариантах: первый допустимый вариант в штатном порядке и дополнительный контроль с тем же расстоянием/частотами. Общая защита и пределы одинаковы, но словари и списки кандидатов различны; разницу нельзя приписывать одному лишь алгоритму поиска. Нативные RU/EN-процессы живут весь прогон; кешируется только последний ответ каждого процесса, чтобы не отправлять одно слово повторно между проверкой и получением вариантов. Кеша всего набора нет.

Режим `layout` дополнительно рассматривает неизвестное исходному языку слово длиной от 2 символов: точное сопоставление клавиш RU/EN, целевой вариант обязательно должен быть словарным. Поддерживается регистр и внутренняя клавиша вроде `ye;yj → нужно`. Существующие слова и полностью заглавные аббревиатуры не преобразуются. Слово, которое после неверной раскладки само стало словарным, автоматически не распознаётся.

Обычная защита использует прежние диапазоны имён с заглавной буквы, кода, URL, цитат, Markdown и личного словаря. Для раскладки разрешён обход только `name_candidate`, поскольку иначе вся латиница и первое слово предложения блокируют преобразование. Остальные диапазоны и личный словарь сохраняются. Это не NER: неизвестное намеренное название может совпасть с ошибочной раскладкой. Новый набор явно проверяет такую неоднозначность.

## Проверочные наборы

Основные прежние наборы: dev40, обычный test160, имена/оформление120, прежний парный80, набор защиты40, последний целевой120, раскладка12, абзацы3. Дополнительно до измерений созданы 46 новых текстов: 20 пар раскладки и 6 буквальных названий/технических строк. Пары и дополнительные контролы авторские, а не экспертный независимый экзамен. Ещё один прогон guard40 использует ранее заданный `personal-names.json`: это явная настройка, не автоматическое распознавание и не доступ к полю protected.

Всего 661 строка на каждый из шести профилей, **3966 проверок**; часть строк повторяется в дополнительном личном профиле. Правила, данные, частоты и код зафиксированы коммитом `d0c01be` до оценки в [protocol-v1.json](protocol-v1.json). После результатов пороги и код не подбираются. Эталоны и protected используются только при подсчёте метрик, не при принятии решений.

## Воспроизведение

```powershell
python -X utf8 benchmarks/dictionaries/prepare.py
python -X utf8 benchmarks/dictionaries/prepare_layout.py
python -X utf8 benchmarks/dictionaries/run.py
python -X utf8 benchmarks/dictionaries/run.py --check
```

Подготовка сохраняет данные и нативные файлы в `E:\korrekta\dictionaries-v1`, проверяя SHA-256 опубликованных wheel и пакетов. Данные из Git фиксируются конкретными ревизиями. Повторный вызов подготовки может получить более новый снимок upstream и тогда требует нового протокола; для точного старого снимка URLs/SHA записаны в `data-manifest.json`. Исследовательский запуск проверяет совпадение локального манифеста с зафиксированным и не принимает изменённый снимок.

Последняя команда не требует E:, Hunspell или больших словарей: проверяет контрольные суммы кода/наборов, полноту сохранённых ответов и общую сводку. Сравнения заново считаются Dart `compare_texts.dart`, дословные диапазоны — `preservation/check_retention.py`. Подготовленные словари и бинарные файлы в Git не включаются. Все строки обрабатываются локально, модели и серверы не нужны.

Загрузка OpenCorpora и построение индекса измеряются отдельно от проверки. `seconds` содержит реальное время вызова движка для конкретного текста без оценки эталонов и записи файла. RSS в метаданных относится ко всему Dart-процессу с одновременно загруженным индексом; память двух нативных процессов не включена. Это не отдельный замер памяти каждого движка и не минимальные требования приложения.
