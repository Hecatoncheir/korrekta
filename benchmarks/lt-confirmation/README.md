# GigaChat → подтверждение LanguageTool

Проверяется один заранее заданный строгий вариант: GigaChat предлагает текст, `text-guard-v1` выделяет допустимые правки, LanguageTool 6.8 проверяет **исходник**, и остаются лишь правки с тем же эффектом среди всех вариантов LT. Одного пересечения диапазонов или отсутствия замечаний к новому тексту недостаточно.

Сравниваются точные позиции UTF-16 и Unicode diff внутри замены. Более широкий неизменённый контекст LT разрешён, другое вхождение такого же слова — нет. Если одно замечание LT требует двух совместных изменений, совпадение только половины не принимается. Подтверждение LT не отменяет защиту имён, словаря и оформления. Недоступность сервера, неполный ответ или неверный диапазон прерывают прогон: незавершённый результат нельзя считать проверкой без ошибок.

Фильтр на Dart получает только исходник, выход модели и ответ LT, без эталонов и разметки набора. Отдельно измеряются прежняя схема GigaChat+Dart, первый вариант LT, первый вариант LT+Dart и строгая связка. Это позволяет отличить пользу двух механизмов от ограничения полноты возможностями LT. Согласие механизмов само по себе не доказывает языковую правильность.

Основной промпт GigaChat прежний `text-json`; вариант с примерами проверяется отдельно. Сырые ответы уже получены в предыдущих реальных запусках. Новая генерация не требуется для основной оценки: это изолирует влияние подтверждения. Все наборы ранее использовались и не являются новой независимой приёмкой. Правило, наборы, исходные ответы и контрольные суммы кода фиксируются перед основными оценками и затем не подбираются.

## Запуск

Нужны уже установленные LanguageTool 6.8 и Java на E:, Dart и существующие зависимости инструмента. Новые библиотеки не устанавливаются.

```powershell
& .\benchmarks\languagetool\Start-LanguageTool.ps1
python -X utf8 benchmarks/lt-confirmation/run.py
python -X utf8 benchmarks/lt-confirmation/run.py --check
```

Последняя команда проверяет сохранённые входы, полноту наборов и сводку без сервера и модели. Повторный расчёт `*-comparison.json` выполняется прежним Dart `compare_texts.dart`. Из `tools/model_benchmark` для произвольного завершённого прогона:

```powershell
dart run bin/confirm_results.dart --input ../../benchmarks/results/2026-11-03/giga20-gfusion/gigachat20-test.jsonl --output-prefix work/lt-confirmed
```

Команда создаёт четыре JSONL: `giga-dart`, `lt-first`, `lt-dart`, `joint`. Существующие файлы не перезаписывает. Полный ответ LT с правилами и всеми заменами сохраняется в `lt-first`/`lt-dart`; фактически подтверждённые диапазоны и отклонения — в `joint.confirmation`. Прогрев LT отделён, кеш ответов сервера выключен, все HTTP-запросы идут на localhost. Прикладное ядро и экспериментальная команда написаны на Dart; Python только организует исследование.

Время связки — сохранённое время GigaChat плюс новые измерения HTTP LT и подтверждения на Dart. Это оценка суммы стадий, не измеренный заново полный запрос приложения. `confirmation_seconds` включает защиту Dart и проверку согласия; `guard_seconds` унаследован от отдельно измеренного профиля GigaChat+Dart и повторно в сумму не включён. Интерфейс Flutter в исследовании не подключается.
