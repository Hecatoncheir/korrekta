# GigaChat выбирает готовые варианты Hunspell

[Результаты 4 ноября 2026](../results/2026-11-04/hunspell-ranker/README.md): ограничение полномочий прошло проверку, улучшения выбора в этом прогоне нет.

Один фиксированный эксперимент: Hunspell 1.7.5 находит неизвестные слова, прежняя защита `dictionary-v1` отбирает допустимые малые замены, GigaChat-20B-A3B-instruct-v1.5 Q4_K_M выбирает **номер** варианта или `0` — оставить исходник. Прикладные сбор вариантов, проверка ответа и применение изменений реализованы на Dart. Python только организует исследование и рендерит официальный шаблон из локального кеша.

## Граница полномочий модели

В каждом списке первым стоит исходное написание, далее до 12 вариантов в штатном порядке Hunspell. Точные дубли убраны, варианты с удалением существующей ё, несколькими словами или слишком большим расстоянием не допускаются. Одновременно предлагается не более 16 диапазонов исходного текста. Защита имён с заглавной буквы, личного словаря, кода, цитат и оформления остаётся прежней.

Модели передаются только `text` и `slots`: исходные слова, позиции UTF-16, списки вариантов с явными `id`. Эталоны, категории и protected в запрос не попадают. Ответ — единственный JSON с числовыми полями `{"c0":0,"c1":1,...}`: ключ соответствует id диапазона, значение — id варианта. JSON Schema отдельно перечисляет допустимые номера каждого поля. Модель не получает поля для исправленного текста, замены или новых координат.

Dart проверяет структуру, точный набор полей, целочисленность и наличие номера в каждом конкретном списке. Все диапазоны сверяются со снимком и проверяются на пересечение. Неверный или незавершённый ответ целиком отклоняется; ошибкой отмечается весь случай, а не только плохой номер. Выбранный результат нельзя применить к изменённому тексту. Никакой свободный текст модели в документ не вставляется.

Это ограничивает изменения, но не доказывает правильность выбранного словарного варианта. Вариант может быть грамматически или семантически неуместен. Для неизвестного имени доступен отказ `0`, а для известного личному словарю имени диапазон вовсе не передаётся модели.

## Что сравнивается

Для каждого текста используются **одни и те же ограниченные списки**:

1. Первый допустимый вариант Hunspell.
2. Минимальное OSA-расстояние, затем максимальная частота из прежнего списка, при равенстве штатный порядок.
3. Реальный выбор GigaChat из вариантов, включая отказ.

Первый вариант и частотное ранжирование не вызывают модель. Третий режим вызывает модель только при непустых списках. Кеша ответов GigaChat нет. Холодный запрос отделён и повторён в основной последовательности. Отсутствие вариантов не считается доказательством отсутствия ошибки: предложение просто остаётся без изменений.

Основной режим `spelling` предлагает только варианты Hunspell. Дополнительный `layout` также предлагает прежнее преобразование клавиш RU/EN, если целевой вариант признан словарём Hunspell. Это отдельный детерминированный кандидат, а не штатная подсказка Hunspell. Защита `name_candidate` в этом дополнительном режиме имеет прежнее исключение; остальные защищённые диапазоны и личный словарь не обходятся.

Все десять наборов/настроек из предыдущего словарного исследования: 661 строка × два режима, всего 1322 случая. В дополнительном личном профиле повторяются 40 текстов с фиксированным `норвета`, `ливея`; это ручная настройка. Наборы уже использовались в разработке, независимой новой приёмкой не являются. Один промпт и параметры зафиксированы до отбора, после просмотра результатов не подбираются.

## Достижимость эталона

После получения ответов отдельно считается, можно ли вообще составить точный эталон из предложенных вариантов и неизменённых промежутков исходника. Это диагностический потолок по ограниченному списку, не автоматический отбор по эталону. Значение не передаётся ни Hunspell, ни модели. Если правильного слова нет среди вариантов, никакой допустимый ответ модели не сможет его добавить; грамматика и пунктуация вне диапазонов тоже недоступны.

## Совместимость формата

Первоначальный контракт v1 с массивом `choices` не прошёл техническую проверку: все 311 непустых запросов вернули некорректный JSON (например, пропущенную открывающую скобку). Эти ответы не оцениваются как качество выбора. Полный прогон, входы и исходный код сохранены в `array-v1`, первоначальный `protocol-v1.json` не заменён.

V2 меняет только форму ответа на поля `c0..cN` и ограничивает каждое своим enum. Списки кандидатов дословно те же, их SHA совпадает. Сбор кандидатов и словарная защита также не менялись; это проверено сравнением исходного кода до парсера. Перед основным v2 выполнена отдельная успешная проба. После неё модель выгружена, чтобы первый измеряемый запрос v2 отдельно включал загрузку. Протокол v2 и входы зафиксированы до успешного отбора; на результатах качества промпт не настраивался.

## Воспроизведение

Нужны прежние словари и Hunspell в `E:\korrekta\dictionaries-v1`, локальные веса GigaChat в `E:\ollama\models`, отдельный Ollama 0.40.13 на `127.0.0.1:11435`, существующие Dart и среда подготовки. Новые библиотеки и веса не устанавливаются.

```powershell
python -X utf8 benchmarks/hunspell-ranker/run.py --phase prepare
python -X utf8 benchmarks/hunspell-ranker/run.py --phase probe
python -X utf8 benchmarks/hunspell-ranker/run.py --phase run
python -X utf8 benchmarks/hunspell-ranker/run.py --phase evaluate
python -X utf8 benchmarks/hunspell-ranker/run.py --phase check
```

Подготовка создаёт `candidates.jsonl`, `rendered.jsonl` и `preparation.json` с контрольными суммами **до первого запроса модели**. Рендеринг офлайн, токенизатор ревизии `8a6075316cd6d41269f7892caf046f7d5aa274a4`, дополнительные специальные токены передаются явно. Проверяется предел входа 3712 токенов. Отбор использует raw API, JSON Schema, temperature 0, seed 42, контекст 4096, максимум 256 токенов ответа, repeat penalty 1.0, без размышления.

Используется `protocol-v2.json`. Последний этап проверяет сохранённые входы, структуру наборов, происхождение ответов, профили и сводку без движков и E:. Для повторного расчёта метрик используется прежний Dart `compare_texts.dart`. Полные ответы GigaChat и выбранные номера сохраняются в `responses.jsonl`; `*-giga.jsonl` содержит итог для общей оценки.

Время подготовки вариантов и HTTP-запроса измеряется отдельно; суммарное `seconds` — сумма стадий, выполненных в разных фазах, а не новый замер полного приложения. У случаев без вариантов время модели нулевое. Сырые результаты содержат исключения и причины отказа, поэтому сбой нельзя принять за правильное отсутствие подсказки. Интерфейс Flutter в исследовании не подключается.
