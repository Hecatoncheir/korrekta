# GigaChat выбирает варианты Hunspell: 4 ноября 2026

**Вывод:** ограничение полномочий работает, но в этом прогоне GigaChat не улучшил выбор исправлений. В основной оценке все 311 ответов с вариантами прошли строгую проверку; независимое восстановление результата не обнаружило изменений вне предложенных диапазонов. Полнота оказалась ниже первого или частотного варианта Hunspell. Для автоматического движка эту конфигурацию не выбираем; M1 остаётся открытым.

## Условия

GigaChat-20B-A3B-instruct-v1.5 Q4_K_M через отдельный локальный Ollama 0.40.13; прежний Hunspell 1.7.5 и общая Dart-защита `dictionary-v1`. Модель возвращает только номера готовых вариантов или `0` — оставить слово. Сбор вариантов, проверка структуры, снимка и применение замен реализованы на Dart. Эталоны модели не передаются. [Протокол и воспроизведение](../../../hunspell-ranker/README.md), [зафиксированный v2](../../../hunspell-ranker/protocol-v2.json).

661 строка/настройка × два режима = **1322 случая**. Из них 1011 без вариантов, поэтому модель не вызывается; 311 с реальным запросом, без кеша ответов. 227 ответов выбрали хотя бы одну замену, 84 сохранили все слова. Личный профиль повторяет 40 текстов с заранее заданными именами, поэтому это не 661 уникальный текст. Все наборы уже использовались ранее: новой независимой приёмкой результаты не являются.

Одинаковые ограниченные списки сравниваются тремя способами: первый вариант, расстояние+частота, выбор GigaChat. До 12 замен и исходник на слово, до 16 диапазонов. Независимая проверка показала, что эти ограничения не изменили результаты двух словарных базовых профилей относительно предыдущего исследования.

## Основной режим: только варианты Hunspell

Число полностью исправленных текстов с ошибками **без лишних изменений**. Последняя колонка — сколько эталонов вообще можно составить из этих списков и неизменённых промежутков. Это диагностический потолок, рассчитанный после выбора, а не подсказка для модели.

На обычном наборе точность отдельных фактических замен GigaChat составила 100%, первого варианта — 90%, частотного — 85%; это достигнуто ценой меньшего числа исправлений. На оформлении точность GigaChat уже **88%**: допустимое слово из списка тоже может оказаться неверным. Единицы этой метрики — отдельные эффекты замен, а таблицы — целые тексты.

В правильных контролях основной режим не меняет тексты обычного набора (0/64), оформления (0/60), holdout80 (0/40), precision120 (0/60), dev (0/16), layout12 (0/4). На guard40 первый и частотный варианты меняют 1/20 контролей, GigaChat — 0/20; с личным словарём все дают 0/20. На layout46 **все три дают 1/26 ложное изменение**, поэтому общей гарантии сохранности имён нет. Проверки размеченных защищённых фрагментов у GigaChat: ноль нарушений на preservation/holdout80/guard40/precision120 и одно на layout46. Отсутствие изменения вне кандидатов не означает отсутствие изменения имени внутри кандидата.

## Дополнительный режим раскладки

Кроме предложений Hunspell здесь разрешено прежнее преобразование клавиш RU/EN, если результат подтверждён словарём. Это отдельный кандидат, а не штатная подсказка Hunspell.

| Набор | Первый вариант | По частоте | GigaChat | Изменённые правильные контроли: первый / частоты / GigaChat |
|---|---:|---:|---:|---:|
| Layout12, 8 ошибок | 7 | 7 | 2 | 0 / 0 / 0 из 4 |
| Layout46, 20 ошибок | 19 | 19 | 2 | 2 / 2 / 1 из 26 |

На остальных наборах результаты близки к основному режиму, но GigaChat теряет ещё по одному чистому исправлению на обычном наборе (12), оформлении (20) и precision120 (32). Все значения обоих режимов — в [overview.json](overview.json). Автоматически запускать модель для распознавания раскладки по этим результатам невыгодно: она часто отвергает полезные готовые варианты. Для продукта предпочтительнее отдельная команда исправления раскладки выделения с просмотром результата.

## Наблюдаемые примеры

- «Она хочеть увидеть море.»: варианты `хочеть / хочет / хотеть / хочешь`; первый вариант исправляет ошибку, GigaChat выбирает исходник.
- «Список покупок: хлеб, сыр и яблаки 🛒»: варианты `яблаки / яблоки`; GigaChat оставляет опечатку.
- `lj,hjt enhj`: словарный режим раскладки даёт `доброе утро`, GigaChat оставляет оба исходных слова.
- «Участница норвета подготовила короткую заметку.»: модель сохраняет имя, которое оба словарных профиля меняли. Полезный отказ, но для гарантии всё равно нужен личный словарь.

Ранее обсуждавшиеся ложные правки «большинство», «согласно», «утром», «сложа руки», «попроще» в этой схеме не предлагаются Hunspell. Их сохранение обеспечивает ограничение списка; приписывать это пониманию GigaChat нельзя. Орфографические списки не покрывают грамматику, запятые и ошибки в словарно правильных словах. В обычном наборе даже идеальный выбор из текущих списков ограничен **19 из 96** текстов.

## Совместимость, скорость и повторяемость

Первый массивный формат v1 в текущей связке возвращал сломанный JSON на всех 311 основных запросах (например, `{"choices":1]}`). Они целиком отклонены и **исключены из выводов о качестве выбора**. Полный отрицательный прогон сохранён в [array-v1](array-v1/compatibility.json), исходный код — в `benchmarks/hunspell-ranker/array-v1`. Причина взаимодействия модели, схемы и среды отдельно не изолирована.

V2 заменяет массив числовыми полями `c0`, `c1` с отдельными допустимыми значениями. Кандидаты дословно совпадают по SHA; защита и правила выбора не менялись. Отдельная проба v2 успешна, затем модель выгружена и выполнен основной прогон. Протокол и входы зафиксированы до отбора, после оценки промпт не подбирался. Коммиты фиксации: `380a51b`, `ffbf17c`, `cb93b77`.

Параметры: temperature 0, seed 42, контекст 4096, ответ до 256 токенов, repeat penalty 1, без размышления. Официальный шаблон из локального токенизатора ревизии `8a6075316cd6d41269f7892caf046f7d5aa274a4`; максимум входа 564 токена. Холодный запрос основной последовательности — **11,048 с**; медиана HTTP-запросов после него **0,269 с**, p95 **0,430 с** по 311 реальным вызовам. Случаи без вариантов исключены из этих времён. Сумма стадий в `seconds` не является новым измерением полного приложения.

Среди 121 группы повторяющихся дословно одинаковых запросов обнаружена **одна группа с разным выбором**, несмотря на temperature 0 и фиксированный seed (`ordinary/ru-002`, два режима). Причина не установлена; полной повторяемости выбора этот запуск не доказывает. [Независимый аудит](audit.json) проверяет каждый итог по сохранённым номерам и спискам, а также совпадение словарных базовых результатов с прежними.

Новые веса и библиотеки не скачивались. Использованы ранее подготовленные данные на E:. Исследовательский Ollama выгружен и остановлен после проверки. В интерфейс приложения связка не подключена. Следующий обоснованный вариант — локальные словарные подсказки с ручным принятием и личным словарём; для автоматического отбора нужен новый эксперимент и новый независимый набор.
