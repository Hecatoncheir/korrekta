# Крупные SAGE и GigaChat — 3 ноября 2026 года

Проверены три дополнительные модели ai-forever: **SAGE FRED-T5-large, mT5-large и M2M100 1.2B**. Они скачаны на E: и реально запущены на GPU. Повторно проверен установленный GigaChat 3.1: обычный API и отдельный режим с предварительным рендерингом официального шаблона. Новые модели не стали готовой заменой всей системы корректуры: сохранение авторских данных остаётся обязательным отдельным условием.

Из новых SAGE лучшее сочетание результатов на обычных фразах дала **mT5-large**. На текстах с оформлением все три большие SAGE уступили LanguageTool по числу исправлений без побочных изменений. **GigaChat с отдельными JSON-правками** исправил больше таких текстов, чем LanguageTool, но чаще предлагал лишние изменения. Он остаётся кандидатом для дополнительного слоя грамматических подсказок с проверкой правок, а не выбранным автоисправлением.

## Какие ещё модели есть у Сбера

- [SAGE FRED-T5-large](https://huggingface.co/ai-forever/sage-fredt5-large) — специализированная русская орфография и пунктуация; проверена здесь.
- [SAGE mT5-large](https://huggingface.co/ai-forever/sage-mt5-large) — орфография русского и английского; проверена здесь. Авторы отдельно указывают необходимость дальнейшей настройки для лучшего качества на русском. Результаты `ft` и облачного `sage-ai-service` из карточки не являются результатами скачанных весов.
- [SAGE M2M100 1.2B](https://huggingface.co/ai-forever/sage-m2m100-1.2B) — специализированный русский корректор на архитектуре M2M100; проверен здесь. Архитектуры mT5 и M2M100 исходно разработаны другими командами, здесь используются адаптации ai-forever.
- [GigaChat 20B-A3B v1.5](https://huggingface.co/ai-sage/GigaChat-20B-A3B-instruct-v1.5-GGUF) — есть публичный GGUF Q4_K_M размером около 12,5 ГБ. В эту итерацию не включён: выбран уже установленный более новый компактный GigaChat 3.1 и специализированные корректоры. Совместимость и качество 20B здесь не измерены.
- [GigaChat 3.5 Reasoning](https://huggingface.co/ai-sage/GigaChat3.5-432B-A28B-Reasoning-GGUF) — 432B параметров, 28B активных. Оценка только весов при 4 битах — примерно 216 ГБ, без дополнительных расходов. Такой локальный запуск не соответствует имеющимся 32 ГБ RAM и 12 ГиБ VRAM; модель не скачивалась. Публичная серия 3.1 Ultra ещё крупнее, 702B.
- [GFusion 10B-A1.8B](https://huggingface.co/ai-sage/GFusion-10B-A1.8B) — экспериментальная диффузионная языковая модель с отдельным механизмом генерации и пользовательским кодом. Это другой исследовательский вариант, не проверенный здесь корректор.

## Условия и веса

Windows 11, Ryzen 9 3900XT, 32 ГБ RAM, RTX 3080 Ti 12 ГиБ. SAGE: Transformers 5.22.1, PyTorch 2.11.0+cu128, FP32, seed 42, без sampling. ## Обычные фразы: test 160

96 ошибочных и 64 правильных текста. Общая метрика `text-effects-v1` оценивает конечный текст. Выполнение эталонной ошибки может сочетаться с ошибкой в другом месте; отдельная колонка требует полного правильного результата. [Все оценки](comparison-test.json), [компактная сводка](overview.json).

| FRED-T5-large | 74 | 65 | 4 |
| M2M100 1.2B | 41 | 30 | 16 |

mT5 выполнила 74,0% эталонных ошибок и изменила 4,69% правильных текстов. Атомарная точность diff — 89,2%. Это не подтверждает ориентир 95% точности карточек и не переносится автоматически на другие виды текста. У FRED больше выполненных ошибок, но меньше полностью правильных исправлений: размер и полнота сами по себе не определяют пригодность.

## Имена, эмодзи и оформление: 120 текстов

60 правильных и 60 с ошибкой, то есть 60 парных контекстов. Для GigaChat берётся итог после отклонения отсутствующих, неоднозначных и пересекающихся фрагментов. Все сырые предложения, включая отклонённые, также сохранены. [Общее сравнение](comparison-preservation.json), [защищённые фрагменты](retention.json).

| Вариант | Ошибок выполнено / 60 | Исправлено без лишних изменений / 60 | Изменено правильных / 60 | Повреждён protected, текстов / 120 |
| --- | ---: | ---: | ---: | ---: |
| LanguageTool | 26 | 23 | **10** | 20 |
| SAGE 95M | 38 | 7 | 46 | 90 |
| FRED-T5-large | 45 | 12 | 47 | 82 |
| M2M100 1.2B | 41 | 12 | 40 | 80 |
| mT5-large | 44 | 16 | 42 | 82 |
| **GigaChat 3.1, обычный API** | **43** | **40** | **13** | **9** |
| GigaChat 3.1, raw | 48 | 46 | 25 | 8 |

GigaChat через обычный API дал 40 чистых исправлений против 23 у LanguageTool, но изменил 13 правильных текстов против 10. Сырые замечания к правильным текстам — **35/60** для обычного API и **46/60** для raw; после валидации остаётся меньше изменений. Это преимущество всей схемы «отдельные предложения + проверка диапазонов», а не доказательство надёжности всех ответов модели. У SAGE здесь применяется полный выходной текст; аналогичная защита извлечённых правок для неё ещё не реализована.

Примеры нежелательного поведения:

- FRED удаляет точку в правильной фразе `В заметке «Северное окно» автор описывает прогулку.`.
- M2M100 меняет `«Нотолист»` на `«Нота-лист»`.
- mT5 меняет кавычки в `„Письмо к морю“` и теряет форматирование.
- GigaChat через API меняет `„Письмо к морю“` на `«Письмо к морю»`, а в `«Завтра будет встреча»` добавляет `значит`.

Намеренные пробелы, отступы и технические строки считаются данными автора; такие изменения не скрываются нормализацией. Результат не является рейтингом всех возможностей моделей, а проверяет конкретный контракт Корректы.

## Что показала проверка шаблона GigaChat

Те же GGUF Q4_K_M и Ollama 0.40.13. Для raw использован официальный `chat_template.jinja` ревизии `189fff27a1dee68473960c3d5bca53e0e07a3191`, SHA-256 `e0b8ec1e172a124fe688e705a6e48fc30c575c23dae7388e43007f150d8343a3`. Токенизатор и шаблон скачаны отдельно, BF16-веса не загружались. Промпт и JSON-схема v1 не менялись.

В текущем `/api/show` возвращён тот же Jinja по контрольной сумме; в старом отчёте было `{{ .Prompt }}`. Однако **все 160 итоговых текстов и все 160 JSON с предложениями обычного API совпали с первым исследованием**. Поэтому прежние результаты качества GigaChat не объявляются неправильными из-за поля шаблона.

Raw и обычный API на dev дали разные итоги в 24/40 случаях. Подача различалась, в частности, сериализацией входного JSON; причинно изолировать влияние только шаблона по этому опыту нельзя. Практический результат: предварительный рендеринг не улучшил консервативность и не выбирается предпочтительным режимом. Синтаксически правильные JSON получены во всех полных новых прогонах обоих режимов; это не подтверждает языковое качество.

## Скорость, раскладка и ограничения

Повторные короткие запросы test, медиана / p95: FRED **0,380 / 0,539 с**, M2M100 **0,393 / 0,555 с**, mT5 **0,534 / 0,734 с**, GigaChat API **0,260 / 0,363 с**, raw **0,185 / 0,241 с**. Первый запрос отделён; интерфейс, принятие правок и реальные пользовательские документы не измерялись. Это разные среды и форматы ответа: FP32 Transformers против Q4 Ollama с JSON-объяснениями.

На FRED и M2M100 все 332 повторных запроса завершились EOS. У mT5 7/332 дошли до предела генерации: четыре смешанных примера оформления и три пробы раскладки. На 160 обычных test-текстах таких случаев не было. После просмотра test лимит не увеличивался; это остаётся ограничением измеренной конфигурации.

Раскладка: строгого восстановления не получилось ни у одного варианта — **0/8**. При игнорировании только регистра и конечных `. ! ?` raw GigaChat восстановил один пример `Ghbdtn` → `привет`, остальные варианты — 0/8. При этом raw изменил все четыре правильных технических контроля, обычный API — два, mT5/M2M100/SAGE 95M — по одному. Маленькая проба не подтверждает надёжную поддержку раскладки; отдельный механизм на Dart по-прежнему нужен. [Сводка проб](overview.json).

Наборы уже использованы в исследовании; ни подбор по этим ответам, ни итоговая независимая приёмка не выполнялись. Сравнения со старыми SAGE 95M и LanguageTool используют сохранённые ответы, а не синхронные новые прогоны. Устройства и методики сравнения скорости различаются. После реализации ограничений правок потребуется новый набор и полноценный маршрут Flutter → движок → валидация → подсказки.

## Решение для M1

Большие SAGE не выбираются единым движком для замены всего текста. mT5-large можно сохранить как кандидата для обычных фраз или будущей настройки, но сама по себе она не обеспечивает сохранность оформления. LanguageTool остаётся быстрым источником правил и подсказок. GigaChat через обычный API перспективен как дополнительный источник грамматических правок с явным принятием и усиленной проверкой, однако ложных предложений пока слишком много.

**Ни один вариант не объявлен готовым движком по умолчанию; M1 открыт.** Следующий шаг — проверять допустимость каждой фактической замены, защищать авторские данные и оформление и повторно измерять полноту после фильтрации. Защита ещё не реализована. Веса новых моделей оставлены на E:, исследовательский экземпляр Ollama на 11435 остановлен и GPU освобождён. LanguageTool на 8081 продолжает работать. Существующие модели и системные установки сохранены.
