# Запрос и формат ответа GigaChat — 3 ноября 2026 года

**Формат запроса заметно влияет на результат.** Вариант с исправленным текстом без объяснений стал гораздо реже менять правильные фразы. На новом отложенном наборе это сопровождалось дополнительными пропусками ошибок; на прежнем наборе обычных фраз улучшились оба показателя. Готовность всего движка по одному из этих результатов не объявляется.

[Статья Сбера](https://giga.chat/help/articles/ai-text-editor) описывает онлайн-редактор и рекомендует явно задавать задачу. Она не раскрывает модель и внутренний системный запрос этого режима. Здесь проверен локальный GigaChat 3.1, а не работа сайта через СберID. Режимы делового стиля, сокращения и стилистической переработки не смешивались с корректурой.

## Условия

Те же GGUF Q4_K_M, Ollama 0.40.13, обычный `/api/chat`, RTX 3080 Ti 12 ГиБ, Ryzen 9 3900XT, 32 ГБ RAM. Temperature 0, seed 42, context 4096, predict 768, repeat penalty 1, think false. Вход для всех вариантов — одинаковый JSON `text` в сообщении пользователя. Новые веса и зависимости не загружались. [Протокол](../../../gigachat-prompts/protocol-v1.json), [точные запросы и команды](../../../gigachat-prompts/README.md), [замороженные суммы](../../../gigachat-prompts/checksums-v1.json).

Изменены не только слова инструкции, но и сложность ответа: подробный JSON с правками и правилами сравнивается с исправленным текстом целиком. Поэтому не утверждается, что эффект дала исключительно длина промпта или исключительно отсутствие объяснений. Промпты, новый набор и правило выбора зафиксированы до dev-прогонов. После просмотра test и нового набора они не менялись.

## Выбор на dev

Прежние 40 dev-текстов: 24 с ошибкой и 16 правильных. [Сохранённый выбор](selection.json), [общая оценка](dev-comparison.json).

| Запрос / ответ | Чистых исправлений / 24 | Изменено правильных / 16 | Балл отбора |
| --- | ---: | ---: | ---: |
| Прежний подробный список JSON-правок с объяснениями | 17 | 7 | 3 |
| Короткий запрос, тот же список правок | 0 | 0 | 0 |
| **Только исправленный текст** | **17** | **1** | **15** |
| Исправленный текст в одном JSON-поле | 17 | 1 | 15 |

Балл — число чистых исправлений минус два штрафа за каждый изменённый правильный текст и четыре за каждый сбой контракта. При равенстве применяется заранее заданный порядок. По этому правилу выбран [text-only.txt](../../../gigachat-prompts/text-only.txt). Короткий запрос с массивом `edits` почти всегда возвращал пустой массив: осторожность без исправлений не считается улучшением. Два текстовых режима на dev равны по основным результатам; второй на test не проверялся, поэтому предпочтительность plain text над одно-полевым JSON на новых текстах не установлена.

## Новый отложенный набор: 80 текстов

40 новых парных контекстов: 40 правильных и 40 с одной внесённой ошибкой. Пары охватывают обычные фразы, имена, кавычки, эмодзи, отступы, ссылки, пути и код. Точных совпадений с прежними наборами нет. Это авторская внутренняя проверка, не 80 независимых контекстов и не внешний языковой рейтинг. [Оценка каждого примера](holdout-comparison.json).

| Вариант | Эталонных ошибок выполнено / 40 | Исправлено без лишних изменений / 40 | Изменено правильных / 40 | Полностью правильный итог / 80 |
| --- | ---: | ---: | ---: | ---: |
| Прежний запрос, JSON-правки после валидации | 31 | 31 | 17 | 54 |
| **Выбранный запрос, только текст** | **27** | **24** | **2** | **62** |

Новый вариант изменил 5% правильных текстов против 42,5%, но выполнил только 67,5% эталонных ошибок против 77,5%. Чистых исправлений стало на семь меньше. Атомарная точность diff выросла с 59,2% до 81,8%; это отдельная метрика, а не подтверждение 95% точности карточек.

Оба нежелательных изменения правильных текстов у выбранного запроса:

- `Она уверена, что название „Медный сад“ подходит книге.` → кавычки заменены на `«Медный сад»`.
- `Ответ:  версия уже доступна для установки.` → два намеренных пробела сокращены до одного.

Защищённые фрагменты нарушены в 5/80 текстов у выбранного варианта и 6/80 у прежнего. [Проверка сохранения](holdout-retention.json). Это не устранённая проблема, несмотря на заметное уменьшение ложных изменений правильного текста.

## Контракт и скорость

Во всех новых полных прогонах получены ответы без ошибок транспорта, нарушения заданной структуры или остановки по лимиту. Для plain text `schema_valid` означает только непустую строку; полезность и отсутствие вступлений проверяются совпадением итогового текста с эталоном. Никакие пояснения, кавычки и переносы не удалялись ради оценки.

На новом holdout медиана / p95: прежний запрос **0,270 / 0,386 с**, только текст **0,086 / 0,106 с**. Измеряется локальный запрос и чтение ответа, без оценки и записи файла. Объяснения генерируются только в исходном режиме, поэтому это разные объёмы работы. Время будущей отдельной генерации объяснений не измерено.

Статистика `precision` в служебных `summary` для текстовых ответов относится к целому изменённому тексту и не сравнивается напрямую с точностью отдельных карточек. Все таблицы выше используют один общий `text-effects-v1`. Для исходного JSON оценивается итог после отбрасывания недопустимых предложений; сырой ответ также сохранён.

## Решение для Корректы

Проверка поддерживает идею явно разделить задачи: сначала минимальная корректура, затем вычисление правок и проверка защищённых диапазонов на Dart, затем при необходимости объяснение уже выявленной правки. Простой запрос — полезный кандидат для первого шага, но не готовое автоисправление. Второй и третий шаги ещё не реализованы.

Просьбы улучшить стиль, сделать текст деловым или лаконичным должны оставаться отдельным действием. Для основного корректора они меняют критерий правильности. Модель и её прежние результаты не объявляются бесполезными: измерения относятся к конкретной инструкции, формату ответа и пути валидации.

M1 остаётся открытым. Следующая проверка — превратить текстовый ответ в локальные правки, защитить данные автора и измерить, сколько полезных исправлений сохранится после фильтрации. Исследовательский сервер Ollama остановлен, веса остаются на E:, LanguageTool продолжает работать. Интерфейс Flutter в этой проверке не создавался и не изменялся.
