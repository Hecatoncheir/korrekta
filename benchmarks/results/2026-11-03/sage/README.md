# SAGE 95M — результаты 3 ноября 2026 года

**Дополнение:** [проверка 120 новых текстов с оформлением](../preservation/README.md) выявила частую потерю имён, эмодзи, кавычек и переносов. Предварительная рекомендация взять SAGE 95M за основу отозвана; результаты первого набора ниже сохранены без изменений.

SAGE успешно запущена на текущем компьютере через Transformers, отдельно от Ollama. Проверены 200 коротких текстов на GPU, 40 подготовительных текстов на CPU и три длины абзаца на обоих устройствах. По общему сравнению итогового текста SAGE реже вносит лишние изменения, чем проверенные GigaChat и Qwen, но пропускает много грамматических ошибок. Модель по умолчанию пока не выбрана, M1 остаётся открытым.

## Модель и оборудование

- `ai-forever/sage-fredt5-distilled-95m`, MIT, ревизия `ed51b4a46603931380951a3d8456685c9215864f`, 95 634 816 параметров, FP32.
- Веса `model.safetensors`: **382 561 704 байта** (382,6 МБ / 364,8 МиБ). SHA-256 `e005b48ae460cbf5f82f0f3da8b13d5df7c2c98eb1e02ed8a7d525d3de7a9bfe` совпал с LFS-метаданными официального репозитория.
- Windows 11 x64, Ryzen 9 3900XT, 32 ГБ RAM, RTX 3080 Ti 12 ГиБ; то же оборудование, что в [исходном отчёте](../README.md).
- Python 3.13.15, PyTorch 2.11.0+cu128, Transformers 5.22.1; `eval`, `inference_mode`, greedy, seed 42, 12 потоков CPU. [Протокол](../../../sage/protocol-v1.json), [команды и окружение](../../../sage/README.md).
- Модель не получала промпт и не генерировала объяснения. Конфигурация и веса не редактировались. Transformers сохранил различающиеся shared/LM-head веса и сообщил, что очистка пробелов для BPE не применяется. Поэтому поведение старого примера авторов на Transformers 4.39 не считается автоматически идентичным этому запуску.

Все веса и окружение находятся на E:. Окружение Python занимает 4,75 ГБ, кеши pip и Hugging Face вместе 3,58 ГБ, суммарно около 8,33 ГБ на момент замера. Это объём исследовательской установки с CUDA и кешем загрузок, а не размер будущего установщика. Веса и зависимости не включены в Git. Исходная установка Ollama и другие модели сохранены.

## Качество на 160 примерах test

96 текстов с эталонной ошибкой, 64 правильных. Для всех четырёх моделей заново посчитан **одинаковый diff итогового текста** (`text-effects-v1`), без новых запросов к Ollama. [Полные числа и оценка каждого примера](comparison-test.json).

| Модель | Точность участков diff | Исправлено эталонных ошибок | Изменено правильных текстов | Итог полностью совпал с эталоном |
| --- | ---: | ---: | ---: | ---: |
| **SAGE 95M** | **89,9%** (71/79) | 67/96 — 69,8% | **4/64 — 6,25%** | **126/160 — 78,8%** |
| GigaChat 3.1 | 64,6% (82/127) | 71/96 — 74,0% | 21/64 — 32,8% | 110/160 — 68,8% |
| Qwen 3.5 4B | 71,6% (63/88) | 54/96 — 56,3% | 7/64 — 10,9% | 110/160 — 68,8% |
| Qwen 3.5 9B | 72,8% (75/103) | 70/96 — 72,9% | 10/64 — 15,6% | 124/160 — 77,5% |

Точность участков diff и точность предложенных карточек из исходного отчёта — разные метрики; проценты нельзя подставлять друг вместо друга. Общая оценка выше рассматривает только применимый итог Ollama, без дополнительного штрафа за отклонённые предложения и неправильный JSON. Структурные ошибки SAGE здесь неприменимы: её контракт — обычный текст. Время и качество объяснений также не проверялись.

На dev SAGE выполнила 15 из 24 эталонных исправлений, сохранила все 16 правильных текстов; CPU и GPU дали одинаковые выходы во всех 40 примерах. [Сравнение dev](comparison-dev.json).

### Где помогает и где пропускает

| Категория test | Полностью исправленные эталонные ошибки |
| --- | ---: |
| Формы глаголов | 13/16 |
| Согласование | 7/16 |
| Орфография | 14/16 |
| Пунктуация сложного предложения | 15/16 |
| Управление и формы слов | 3/16 |
| Другая пунктуация | 15/16 |

Примеры пропусков: «Ребёнок учиться в третьем классе», «Она доволен результатом», «Мы обсудили о проблеме» остались без исправления. В «Вопреки прогноза день оказался солнечным» модель предложила «Вопреки прогнозам, день оказался солнечным»: это не эталонная минимальная правка, изменено число существительного. В примере со словом «счатья» исправлена опечатка, но дополнительно нормализовано допустимое «рожденья» → «рождения».

Все четыре изменения правильных фраз:

- «Наконец, перейдём к последнему вопросу.» → удалена запятая.
- «Лев Толстой написал «Войну и мир».» → заменены кавычки на прямые.
- «Проект называется «Тихий берег».» → заменены кавычки на прямые.
- «Я уже всё проверил 🙂» → удалён эмодзи и добавлена точка.

Строгий эталон не описывает все допустимые варианты пунктуации и формулировок. Эти ответы сохранены для ручного разбора, а не скрыты нормализацией. Набор небольшой, синтетический и уже использован при исследовании моделей; результат не является независимым языковым рейтингом.

## Скорость и память

Первый запрос отделён от повторных. На GPU test: чтение и размещение модели 1,92 с, первый запрос 0,43 с, повторные **медиана 0,131 с / p95 0,192 с**. На CPU dev: загрузка 1,68 с, первый запрос 0,169 с, повторные **медиана 0,171 с / p95 0,225 с**. Это разные части набора; для прямого сравнения CPU/GPU на dev GPU-медиана 0,148 с. Время импорта библиотек и скачивания исключено. Сравнение с HTTP-запросами Ollama включает разные накладные расходы и формат ответа.

| Длина абзаца | GPU SAGE | CPU SAGE |
| --- | ---: | ---: |
| 263 знака | 0,777 с | 1,014 с |
| 538 знаков | 1,576 с | 2,137 с |
| 1183 знака | 3,242 с | 4,534 с |

Это по одному повторному запросу на длину, не устойчивые процентили. Во всех трёх абзацах SAGE на CPU и GPU исправила обе заложенные ошибки без дополнительных изменений: 6/6, тогда как сохранённый Qwen 9B — 5/6. Абзацы содержат знакомые конструкции и не добавляют независимых доказательств качества. [Данные сравнения](comparison-paragraphs.json).

Пиковый рабочий набор процесса: около **1,15 ГиБ CPU / 1,27 ГиБ GPU**. Максимум аллокатора PyTorch на GPU: около 384 МиБ занято тензорами, 420 МиБ зарезервировано. Это **не вся VRAM процесса**: память CUDA, драйвера и рабочего стола сюда не входит. CPU-прогон не размещал тензоры на видеокарте. На всех 246 повторных запросах получен EOS, ограничения длины не исчерпаны. После завершения процессы с моделями закрылись.

## Вывод для M1

SAGE 95M заслуживает дальнейшей проверки как небольшой локальный корректор орфографии и пунктуации. На этом компьютере она пригодна для проверки по кнопке даже без GPU. Однако полнота 69,8% немного ниже ориентира 70%, а 6,25% изменённых правильных текстов выше допуска 5%. Порог точности карточек 95% этим исследованием не подтверждён. Покрытие грамматики недостаточно; объяснений ошибок модель не генерирует.

Следующая проверка: сохранение кавычек, эмодзи и форматирования, затем сравнение с более крупной SAGE на dev и новом независимом наборе. Фильтры не должны скрывать реальные ошибки и не считаются проверенными до отдельного прогона. Переход к SAGE в приложении потребует отдельного решения о локальной среде выполнения и пересмотра этапов, которые сейчас ориентированы на Ollama. Реального подключения модели к Flutter, приёмки macOS/Linux и подтверждения минимального оборудования пока нет.
