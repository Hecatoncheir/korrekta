# LanguageTool 6.8 и связка с SAGE — 3 ноября 2026 года

LanguageTool 6.8 скачан на E: и запущен скрытым локальным процессом Java. Проверен настоящий маршрут Dart → HTTP → LanguageTool на 200 коротких текстах и трёх абзацах. Дополнительно 200 текстов проверены последовательно LanguageTool → SAGE 95M FP32 на CPU. Ollama для этих вариантов не требуется. К интерфейсу приложения они пока не подключены.

## Установка и запуск

LanguageTool 6.8, дата сборки из ответа API `2026-05-05 16:34:58 +0200`, `premium=false`. Источник — опубликованные пакеты Maven Central, а не ZIP 6.6. Среда — Temurin JRE 21.0.13+9 Windows x64, Maven 3.9.11 только для получения зависимостей. [Команды повторного запуска](../../../languagetool/README.md), [протокол](../../../languagetool/protocol-v1.json), [список установленных библиотек и их SHA-256](installation-manifest.json).

Библиотеки LanguageTool занимают около **263 МБ**, Java — **152 МБ**, Maven — **10,7 МБ**, его кеш — **284 МБ**. Архивы Java и Maven вместе — ещё 58,4 МБ. Общая дополнительная исследовательская установка — около 768 МБ; это не размер будущего установщика. Все перечисленные файлы находятся на E:. Архивы Java и Maven проверены по опубликованным контрольным суммам, зависимости получены с проверкой Maven. Системные установки Java и Ollama не заменялись.

Сервер слушает **127.0.0.1:8081**, обращение с других компьютеров не разрешено. Подтверждено работающим сокетом и реальными POST-запросами. Java heap ограничен 1 ГиБ, два потока обработки, кеш ответов отключён. Рабочий набор после прогонов около 500 МиБ, наблюдавшийся пик процесса около **552 МиБ**. Это память процесса, а не требуемый объём RAM всего компьютера. [Замер](server-system.json). Отдельная видеокарта для LanguageTool не используется.

## Результаты test: 96 ошибочных и 64 правильных текста

Один и тот же `text-effects-v1` оценивает конечный текст без нормализации. Для LanguageTool взят первый вариант каждого непересекающегося замечания; альтернативные предложения и сообщения без замены сохранены в сырых ответах. Для связки этот текст целиком передан SAGE, без фильтров и настройки по test. [Общее сравнение](comparison-test.json).

| Вариант | Точность участков diff | Исправлено эталонных ошибок | Изменено правильных текстов | Полное совпадение с эталоном |
| --- | ---: | ---: | ---: | ---: |
| LanguageTool 6.8 | 77,1% — 37/48 | 35/96 — 36,5% | 0/64 — 0% | 99/160 — 61,9% |
| SAGE 95M отдельно | 89,9% — 71/79 | 67/96 — 69,8% | 4/64 — 6,25% | 126/160 — 78,8% |
| LanguageTool → SAGE 95M | 83,7% — 72/86 | 68/96 — 70,8% | 4/64 — 6,25% | 127/160 — 79,4% |

Точность участков diff не равна точности карточек из исходного протокола Ollama. Приёмочный ориентир 95% этим сравнением не подтверждён. Ни ноль ложных замечаний на 64 правильных test-текстах, ни результат одной ошибки прироста не гарантируют такое же поведение на других документах.

LanguageTool выдал 55 замечаний на test; 8 из них не содержали вариантов замены. Ни один из 64 правильных test-текстов не получил даже замечания без замены. Однако на dev правильное «Корректа работает локально» было отмечено как опечатка с первым предложением «Корректор». Всего на dev LanguageTool исправил 10/24 эталонных ошибок и изменил 1/16 правильных текстов. Связка дала 18/24 и 1/16 соответственно; SAGE отдельно — 15/24 и 0/16. [Сравнение dev](comparison-dev.json).

### Почему недостаточно просто применить всё

Примеры первого варианта LanguageTool:

- «Она хочеть увидеть море» → «Она хотеть увидеть море».
- «Пожалуста, закрой окно» → «Пожал уста, закрой окно».
- «Пока ты спал я приготовил завтрак» → «Пока ты спал я, приготовил завтрак».
- «Обоих подруг пригласили на праздник» → «Обе подруг пригласили на праздник».

Другие варианты в списке могут быть лучше первого; их удобство при ручном выборе не измерялось. Сообщение об ошибке и готовая правильная замена — разные результаты. В будущем приложении правки нужно показывать для осознанного принятия, как предусмотрено M3.

У связки по сравнению с SAGE отдельно появились четыре полностью выполненных эталонных исправления и потерялись три; итоговый прирост — одно исправление. Число лишних участков diff выросло с 8 до 14. Ошибка первого этапа может превратиться в правдоподобный неправильный текст, который SAGE уже не исправит. Четыре изменения правильных test-текстов остались теми же: удаление запятой после «Наконец», две замены кавычек и удаление эмодзи с добавлением точки.

## Скорость

На том же Ryzen 9 3900XT / 32 ГБ RAM / Windows 11:

- Первый запрос LanguageTool после запуска: **2,31 с**, включая начальную подготовку русского конвейера. Запрос списка языков до него не проверял текст.
- Повторные запросы test: **медиана 6,9 мс, p95 10,2 мс**, включая локальный HTTP и чтение ответа, без оценки и записи файла.
- Связка LanguageTool → SAGE на CPU test: сумма времён этапов **медиана 0,185 с, p95 0,252 с**. Модель SAGE загружалась отдельно; передача между этапами и холодный старт в эти числа не включены. Это не измеренный пользовательский маршрут готового приложения.
- Абзацы 263 / 538 / 1183 знака: LanguageTool **0,020 / 0,039 / 0,080 с**. Обе заложенные ошибки в каждом абзаце пропущены — 0/6. У SAGE отдельно на CPU было 6/6 за 1,014 / 2,137 / 4,534 с. Для этих трёх абзацев выход LanguageTool равен исходному, но отдельный замер связки на них не выполнялся. [Сравнение абзацев](comparison-paragraphs.json).

Сравниваемые замеры SAGE отдельно сохранены из предыдущего прогона на GPU для test и CPU для dev/абзацев. Качество сравнивается по одинаковому тексту и эталону; скорости на разных устройствах не следует напрямую приравнивать. На 40 исходных dev-примерах предыдущий CPU/GPU-прогон SAGE давал одинаковые тексты, но полная проверка идентичности на test между устройствами не выполнялась.

## Решение для M1

LanguageTool полезен как очень быстрый источник конкретных замечаний, правил, диапазонов и объяснений, но на этом наборе не покрывает большинство требуемых исправлений. Последовательная связка с SAGE не дала заметного улучшения и увеличила число неверных изменений. Она не выбрана как готовый механизм автоматического исправления.

M1 остаётся открытым. Следующий исследовательский вариант — объединять независимые подсказки с явной обработкой конфликтов и сохранением имён, кавычек и эмодзи, а не безусловно переписывать текст одним движком после другого. Любая настройка выполняется на dev; итоговую проверку проводить на новом независимом наборе. Более крупная SAGE также остаётся кандидатом. Окончательный выбор движка и пересмотр этапов M4–M5 после этого ещё предстоят.

LanguageTool оставлен работающим после исследования. Повторный запуск скрипта проверен: второй процесс не создаётся. Регистрация службы или автозапуска Windows, подключение к Flutter и приёмка macOS/Linux не выполнялись.
