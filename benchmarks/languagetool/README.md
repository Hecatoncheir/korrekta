# Локальный LanguageTool 6.8

LanguageTool установлен отдельно на E: и проверен на русском языке. Используется опубликованный выпуск Maven `org.languagetool:languagetool-server:6.8` с русским модулем и стандартными зависимостями `language-all`. Один русский модуль недостаточен для запуска штатного HTTP-сервера: встроенный определитель языка обращается также к другим языковым модулям.

Версия 6.8 найдена в [официальных метаданных Maven Central](https://repo.maven.apache.org/maven2/org/languagetool/languagetool-server/maven-metadata.xml). ZIP 6.6 — последний архив с фиксированным номером; более свежие ZIP публикуются как ежедневные сборки. Поэтому старый `LanguageTool-stable.zip` не использован. [Порядок выпусков](https://dev.languagetool.org/roadmap), [локальный HTTP-сервер](https://dev.languagetool.org/http-server).

## Скачать и запустить на Windows

Из корня репозитория, при установленном Python 3.11 или новее (проверено на 3.13.15):

```powershell
& .\benchmarks\languagetool\Start-LanguageTool.ps1
```

При отсутствии компонентов команда вызывает `prepare.py`, который скачивает проверенные архивы Temurin JRE 21.0.13+9 и Maven 3.9.11, распаковывает их на E: и получает LanguageTool 6.8. Maven используется только для подготовки зависимостей. Затем Java запускается скрытым фоновым процессом. Повторный вызов проверяет уже работающий процесс. Другой процесс на том же порту не останавливается.

Можно задать `-Storage E:\другая-папка -Port 8082`. Подготовку отдельно можно повторить командой `python -X utf8 benchmarks/languagetool/prepare.py`. Системные `PATH` и `JAVA_HOME`, установленный Ollama и его модели не меняются. Нужные переменные передаются только дочернему процессу подготовки. Это исследовательская команда для Windows, а не готовый установщик Flutter-приложения.

Пути по умолчанию:

- `E:\korrekta\languagetool\6.8\lib` — библиотеки LanguageTool.
- `E:\korrekta\runtimes\jdk-21.0.13+9-jre` — Java.
- `E:\korrekta\runtimes\apache-maven-3.9.11` — Maven.
- `E:\korrekta\cache\maven`, `E:\korrekta\downloads`, `E:\korrekta\tmp` — кеш, архивы и временные файлы.
- `E:\korrekta\languagetool\6.8\server-state.json` — PID, порт и время запуска; рядом журналы и список файлов с SHA-256.

SHA-256 Java сверяется с опубликованным значением [официального выпуска Temurin](https://github.com/adoptium/temurin21-binaries/releases/tag/jdk-21.0.13%2B9); SHA-512 Maven — с данными [Maven Central](https://repo.maven.apache.org/maven2/org/apache/maven/apache-maven/3.9.11/apache-maven-3.9.11-bin.zip.sha512). Maven запускается со строгой проверкой опубликованных контрольных сумм зависимостей. Дополнительный список фактически установленных JAR с SHA-256 сохраняется для воспроизводимости. Сами библиотеки в Git не включаются. Лицензия LanguageTool — LGPL 2.1 или новее; лицензии зависимостей также нужно учитывать при будущей упаковке приложения.

## Проверка работы

`http://127.0.0.1:8081/v2/languages` возвращает список языков. Проверка текста выполняется POST-запросом к `/v2/check` с параметрами `language=ru`, `level=default`, `text=...`.

Сервер слушает только `127.0.0.1`, без `--public` и разрешений доступа из произвольных сайтов. Команда запуска ограничивает Java heap до 1 ГиБ. В `server.properties` заданы два потока обработки, кеш ответов выключен, кеш языкового конвейера включён. Облачные ИИ-правила и внешние n-gram модели не настроены. Полное отключение сети при работе не проверялось. Команда не регистрирует службу и автозапуск Windows; после перезагрузки её нужно выполнить снова. Запуск вместе с будущим Flutter-приложением ещё предстоит реализовать.

## Оценка на том же наборе

Из `tools/model_benchmark`:

```powershell
dart run bin/languagetool.dart --data ../../benchmarks/cases-v1.jsonl --split dev --output work/lt-dev.jsonl
dart run bin/languagetool.dart --data ../../benchmarks/cases-v1.jsonl --split test --output work/lt-test.jsonl
```

Путь `--output` здесь задаётся относительно текущего каталога. Файлы не перезаписываются. Сохраняется полный ответ API с диапазонами, объяснениями, правилами и всеми вариантами замены. Для одинаковой оценки итогового текста берётся первый вариант каждого замечания, пересечения отклоняются в порядке API. Замечания без замены считаются отдельно. Это исследовательская условность: пользователь в приложении сможет выбирать другие варианты. Эталон не участвует в выборе.

Диапазоны Java и Dart используют UTF-16; повторяющиеся слова различаются по позиции. Проверены вставки, удаления, пересечения, замечания без вариантов, неправильные диапазоны и позиции после эмодзи. Команда `compare_texts.dart` считает ту же метрику `text-effects-v1`, что для SAGE. [Протокол](protocol-v1.json), [результаты и ограничения](../results/2026-11-03/languagetool/README.md).

Для последовательной проверки LanguageTool → SAGE используются сохранённые ответы, без ручного выбора по эталону. `pipeline.py prepare --lt ФАЙЛ --output ВХОД` создаёт промежуточный набор с выходом LanguageTool вместо исходного текста. SAGE запускается на нём через `benchmarks/sage/run.py --device cpu`; пустые эталоны в промежуточном наборе служебные и не предназначены для оценки качества. `pipeline.py merge --lt ФАЙЛ --sage-stage ВЫХОД_SAGE --output ИТОГ` проверяет совпадение идентификаторов и входа второго этапа и возвращает исходный текст и его эталон для общей оценки. Скорость связки — сумма времён двух этапов без передачи данных между ними; это не измерение готового приложения.
