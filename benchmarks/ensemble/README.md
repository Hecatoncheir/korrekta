# Общий локальный режим

**Текущая рабочая политика:** [выбор по ролям источников](../ensemble-tuning/README.md), [новая независимая проверка](../results/2026-11-04/ensemble-tuning/README.md). Ниже сохранены устройство пула и методика первого сравнения. В рабочей команде `proposed_text` теперь формируется новой политикой, прежнее широкое объединение остаётся в `all_sources_proposed_text`.

Используются все подготовленные источники: общий словарь OpenCorpora + Hunspell, SymSpell на Dart, реальные предложения Hunspell, локальный LanguageTool 6.8 и GigaChat 20B Q4_K_M. [Результаты](../results/2026-11-04/ensemble/README.md).

OpenCorpora — база словоформ, SymSpell — алгоритм поиска близких слов; это не два независимых голоса. Общий словарь признаёт слово известным, если его знает OpenCorpora **или** Hunspell. Каждый механизм по-прежнему предлагает свои замены. Известность словоформы запрещает только словарную коррекцию, а грамматику и контекст дополнительно проверяют LT и GigaChat.

## Прикладное ядро на Dart

- `SharedLexicon` объединяет распознавание слов; приоритет Hunspell использует прежние расстояние и частоты, SymSpell — свой прежний индекс.
- `buildEnsemble` собирает варианты LT, обоих словарных механизмов и допустимые предложения GigaChat на **одном исходном снимке**. Эталонов и разметки тестов в API нет.
- Совпадающие замены объединяются с указанием источников; это свидетельства, а не доказанные вероятности правильности. Конфликтующие диапазоны становятся одним списком альтернатив, включая исходник. Составная правка одного варианта LT целиком проходит защиту и остаётся единым вариантом.
- Общая прежняя защита действует на все предложения: личные имена, заглавные/латинские слова, цитаты, код, ссылки, пробелы, переносы, эмодзи. Защита эвристическая: неизвестное строчное имя без личного словаря может измениться.
- Закрытый выбор GigaChat возвращает только целые `c0..cN`. Новые слова, позиции, свободный ответ и незавершённый JSON применить нельзя. Для запятых поддерживаются пустые исходные диапазоны; пересечения и разрыв UTF-16 запрещены.
- Применение ручного выбора требует того же снимка текста. Все допустимые альтернативы и отклонения остаются в результате.

Публичный Dart API — `tools/model_benchmark/lib/ensemble.dart`. Он подготовлен для дальнейшего Flutter-приложения; нынешний HTML-прототип к движкам не подключён.

## Исходный режим просмотра v1

Объединение заметно расширило покрытие, но сохранило ложные правки. Поэтому рабочая команда готовит **предварительный вариант**, а не перезаписывает документ. Порядок исходного предложения: первый допустимый LT, Hunspell по расстоянию/частоте, SymSpell, допустимая контекстная правка GigaChat. Модель используется как дополнительный источник контекстных исправлений. Общий отбор всех предложений через GigaChat доступен в экспериментальном инструменте: по текущим измерениям он слишком часто отвергает полезные исправления и выбирает неверные варианты.

Из `tools/model_benchmark`, при работающих локальных LT и отдельном Ollama с уже скачанной моделью:

```powershell
dart run bin/ensemble_review.dart --text-file E:/korrekta/my-text.txt --output work/review.json
dart run bin/ensemble_review.dart --text-file E:/korrekta/my-text.txt --names E:/korrekta/my-names.json --output work/review-with-names.json
```

Личный словарь — JSON-массив строк, например `["норвета","ливея"]`, задаётся человеком. Команда никогда не перезаписывает существующий файл результата. Выход содержит `original`, `proposed_text`, `details.slots` с альтернативами и `automatic_application:false`. `review_required` означает необходимость просмотреть изменения, `no_suggestions` — отсутствие найденных вариантов, `incomplete` — сбой одного из источников; последний возвращает код 2. Ни одно состояние не обещает безошибочность. Сбой LT/словарей прерывает обработку, а неполный ответ модели явно отмечается.

Текущий запуск проверен на Windows с данными в `E:/korrekta/dictionaries-v1`; пути и адреса можно передать через `--store`, `--ollama`, `--lt`, `--prompt`. Только localhost, облачные запросы не используются. Новые веса и библиотеки для эксперимента не устанавливались. Для других ОС ещё нужны подготовка нативного Hunspell и отдельная проверка.

## Ограничения

Одна порция — до 1200 символов Unicode, до 32 конфликтующих групп и 32 замен на группу. При превышении лимита обработка прерывается, группы не обрезаются молча. Унаследованный сбор каждого словарного источника ограничен первыми 16 диапазонами и 12 заменами на слово; для LT рассматриваются первые 8 вариантов правила. Контекст Ollama — 8192 токена; консервативная граница по UTF-8 байтам оставляет место ответу. Для измеренного набора официальный токенизатор отдельно проверил все входы выбора: максимум 628 токенов.

Автоматическая раскладка в общем режиме выключена: названия `Ghbdtn` и `руддщ` могут быть намеренными. Прежнее преобразование раскладки остаётся отдельным механизмом для явного выделения. Исправление пробелов, перевод цитат, перефразирование и стилистическое улучшение не входят в этот режим. Правильная последовательность известных слов тоже может содержать ошибку, которую не найдёт ни один источник.

## Эксперимент

Заморожены до оценки: `protocol-v1.json`, 48 новых авторских текстов (24 пары), код и входы. Остальные 400 текстов уже известны; свободные ответы GigaChat для них взяты из прежних запусков, чтобы измерять влияние объединения. Для новых 48 сделаны реальные запросы модели. LT и оба словарных механизма запущены заново для всех 448 текстов. Отдельный закрытый отбор — 237 новых запросов. Один проход, без подбора инструкции после просмотра метрик.

```powershell
python -X utf8 benchmarks/ensemble/prepare.py
# Далее из tools/model_benchmark:
dart run bin/ensemble_check.dart --input ../../benchmarks/results/2026-11-04/ensemble/inputs.jsonl --output work/collected.jsonl --proposal-prompt ../../benchmarks/gigachat-prompts/text-json.txt --selection-prompt ../../benchmarks/ensemble/selection.txt --collect-only
```

Зафиксированные артефакты не перезаписываются. `prepare_selection.py` запускается существующей средой `E:/korrekta/sage-venv/Scripts/python.exe`: офлайн сверяет форму официального шаблона, считает токены и извлекает только записи `case` из завершённого сбора в `selection-input.jsonl`. `--prepared` принимает именно эти записи, без служебного заголовка и итога:

```powershell
dart run bin/ensemble_check.dart --input ../../benchmarks/results/2026-11-04/ensemble/selection-input.jsonl --output work/responses.jsonl --proposal-prompt ../../benchmarks/gigachat-prompts/text-json.txt --selection-prompt ../../benchmarks/ensemble/selection.txt --prepared
# Из корня репозитория, для сохранённых полных результатов:
python -X utf8 benchmarks/ensemble/evaluate.py --check
```

`evaluate.py` проверяет контрольные суммы, происхождение и полноту ответов, точно восстанавливает выбранный результат по UTF-16 диапазонам и сверяет профили/метрики. Режим `--check` не использует E:, модели, Java или сторонние Python-пакеты. Время сохранённой генерации старых текстов не включено в текущую обработку; полной скоростью приложения эти цифры считать нельзя.
