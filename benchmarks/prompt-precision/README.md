# Снижение ложных правок GigaChat 20B

Продолжение исследования после `text-guard-v1`. Меняется только системный запрос. Модель, официальный шаблон, параметры генерации, Dart-защита и метод оценки остаются прежними. Входные тексты обрабатываются локально; Python подготавливает исследование, прикладная логика остаётся на Dart. Новые зависимости не устанавливаются.

## Разбор пяти случаев

| Исходник | Почему изменение не нужно |
|---|---|
| Большинство участников поддержало предложение. | Замена «поддержало» на «поддержали» переключает допустимый вариант согласования. Единственное число здесь не является ошибкой. |
| Согласно приказу занятия отменены. | Добавление запятой навязывает обособление обстоятельства. Исходное необособленное оформление допустимо. |
| Утром было тихо и шёл снег. | Обстоятельство «утром» может относиться к обеим частям; автоматическая запятая перед «и» не требуется. |
| Он сидел сложа руки. | В устойчивом выражении «сложа руки» не обособляется. Механическое правило для деепричастного оборота даёт лишнюю запятую. |
| Можно попроще? | «Попроще» — нормативное слово. Замена на «проще» меняет оттенок просьбы и относится к редактированию стиля. |

Таким образом, «ложная правка» здесь означает ненужное изменение допустимого исходника; результат не обязательно сам по себе неграмотен. Основания: [варианты согласования](https://gramota.ru/biblioteka/spravochniki/pismovnik/edinstvennoe-i-mnozhestvennoe-chislo-skazuemogo), [обстоятельства и устойчивые обороты](https://gramota.ru/biblioteka/spravochniki/pravila-russkoj-orfografii-i-punktuacii/zapyatye-pri-obstoyatelstvennyh-oborotah), [общий второстепенный член](https://gramota.ru/spravka/vopros/319094), [нормативный орфографический словарь, «попроще»](https://gramota.ru/storage/public/normdicts/orfograficheskij_slovar.pdf). При проверке 4 ноября страницы были доступны в поисковой выдаче; прямое открытие части страниц возвращало 403. Новые эталоны авторские, а не экспертная разметка всего набора.

## Заранее заданное сравнение

Первая итерация — три варианта: прежний `text-json`, краткое усиление консервативности `minimal.txt`, явные общие правила пяти классов `rules.txt`. Точные пять старых фраз в промпты не включены. Они вошли в dev и больше не считаются независимой проверкой. Помимо них dev содержит контрпримеры с настоящими ошибками, чтобы не выбрать запрос «ничего не исправлять».

Подготовка `python -X utf8 benchmarks/prompt-precision/prepare.py` создаёт dev80: прежние 40 dev и 20 дополнительных пар. Новый holdout120 содержит 60 пар: пять проблемных семейств по 10 пар и 10 пар с именами/оформлением. В каждой паре один правильный текст и один с ошибкой. Новые тексты не пересекаются дословно с прежними наборами и dev. Это целевая авторская проверка переноса правил, а не внешний независимый рейтинг.

Перед запросами фиксируются контрольные суммы всех промптов, наборов и ядра защиты. Выбор выполняется только по dev после той же автоматической защиты без личного словаря. Допускаются кандидаты с числом чистых исправлений не ниже исходного минус 3 и числом сбоев контракта не выше исходного. Среди них выбирается минимум изменённых правильных текстов, затем максимум чистых исправлений, минимум сырых изменений правильных текстов, затем исходный порядок вариантов. Прежний вариант участвует на равных; улучшение не предполагается заранее.

Только после сохранения выбора выполняются одинаковые новые holdout-запросы для прежнего и выбранного промпта. Для каждого сырого ответа сохраняется результат до/после неизменённого Dart-фильтра. Пороги и промпт после просмотра holdout не меняются. Обычные test160 и preservation120 при дополнительной проверке считаются регрессиями, поскольку уже использованы в исследовании.

## Вторая итерация до нового набора

После первой итерации dev краткий вариант дал 31/44 чистых исправлений и 9/36 изменённых правильных текстов против 29/44 и 10/36 у исходного. Все пять первоначальных ложных правок сохранились. Поэтому до первого запроса нового holdout добавлен четвёртый вариант `examples.txt`: восемь коротких образцов, включая допустимые формы и реальные исправления. Точные пять исходных фраз в образцах не используются.

Это адаптивная разработка по dev. Первый протокол и `selection.json` не заменены; расширение записано в `protocol-v2.json`, новый выбор — в `selection-round2.json`. Наборы, модель, защита, параметры и критерий ранжирования прежние. Окончательная проверка использует только baseline и победителя второй итерации. До этой фиксации новый holdout не запускался.

## Воспроизведение

Из корня проекта, с уже подготовленным отдельным Ollama на `127.0.0.1:11435`:

```powershell
python -X utf8 benchmarks/prompt-precision/run.py --phase dev
python -X utf8 benchmarks/prompt-precision/round2.py --phase dev
python -X utf8 benchmarks/prompt-precision/round2.py --phase test
python -X utf8 benchmarks/prompt-precision/round2.py --phase regression
```

Следующая фаза запускается только после завершения предыдущей. Скрипт проверяет замороженные суммы, использует существующие рендерер официального шаблона и Dart-команды проверки/фильтрации/сравнения. Завершённые выходы пропускаются, незавершённые не перезаписываются. Сырые ответы, отдельные результаты фильтрации, сравнения и выбор сохраняются в `benchmarks/results/2026-11-04/prompt-precision`. Прогресс в `.log` — вспомогательный локальный файл.

`python -X utf8 benchmarks/prompt-precision/verify.py` проверяет полноту результатов, соответствие исходников/эталонов, сохранение сырых ответов и выбор по заранее заданному правилу без модели. Для повторного расчёта метрик служит прежний `tools/model_benchmark/bin/compare_texts.dart`.
