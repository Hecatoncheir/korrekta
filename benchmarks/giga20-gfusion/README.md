# GigaChat 20B и GFusion

Исследование продолжает M1. Модели скачиваются на E:, приложение к ним пока не подключается. Интерфейс и прикладная логика остаются на Flutter/Dart; Python здесь используется для подготовки весов и исследовательского запуска GFusion.

Версии, официальные контрольные суммы, наборы, варианты промпта и правило выбора зафиксированы в [protocol-v1.json](protocol-v1.json). Результаты сохраняются в `benchmarks/results/2026-11-03/giga20-gfusion`.

## Веса и совместимость

- [GigaChat 20B-A3B instruct v1.5](https://huggingface.co/ai-sage/GigaChat-20B-A3B-instruct-v1.5-GGUF): официальный Q4_K_M, 12 494 806 976 байт. Используется уже подготовленный отдельный Ollama 0.40.13 на `127.0.0.1:11435`, облако отключено, контекст 4096. GGUF помещается сразу в хранилище Ollama на E:, повторная копия при регистрации не нужна.
- [GFusion 10B-A1.8B](https://huggingface.co/ai-sage/GFusion-10B-A1.8B): три официальных FP8-файла, всего 11 072 857 344 байта. RTX 3080 Ti имеет compute capability 8.6 и не поддерживает необходимый нативный FP8. Для исследования подготовлена отдельная BF16-копия (21 345 071 232 байта тензоров), из которой при загрузке создаётся NF4 с двойной квантизацией, вычисления BF16. Это дополнительная квантизация исходного FP8, а не проверка исходного FP8 на поддерживаемом оборудовании.

`download.py` получает диапазоны по 64 МиБ четырьмя потоками, проверяет размер и SHA-256. Части находятся в `E:\korrekta\downloads`, завершённые файлы — в кеше Hugging Face или `E:\ollama\models\blobs`. После каждого диапазона сохраняется прогресс. При возобновлении пропускаются записанные завершённые диапазоны; перед переносом файла всё равно проверяется полная сумма. Чужие модели не удаляются.

```powershell
python -X utf8 benchmarks/giga20-gfusion/download.py
```

После скачивания завершите снимок GFusion через `snapshot_download` с закреплённой ревизией и `allow_patterns=['*.json','*.jinja','*.py','*.safetensors','README.md']`. Кеш — `E:\korrekta\cache\huggingface`. Затем:

```powershell
E:\korrekta\sage-venv\Scripts\python.exe -X utf8 benchmarks/giga20-gfusion/convert_gfusion.py
```

Конвертер проверяет исходные SHA-256, умножает каждую FP8-матрицу в FP32 на сохранённые масштабы блоков 128×128 и переводит результат в BF16. Остальные тензоры копируются с исходными значениями. Результат и суммы каждого нового файла — в `E:\korrekta\gfusion\bf16-96199b4`. Уже существующий каталог конвертер не перезаписывает.

Для GFusion используются PyTorch 2.11.0+cu128 из существующей среды, Transformers 4.57.6 из ранее подготовленного `E:\korrekta\sage-transformers4`, отдельные accelerate 1.15.0 и bitsandbytes 0.50.2 в `E:\korrekta\gfusion-packages`. Основная среда SAGE и системные библиотеки не заменяются. Первичные источники библиотек: [Accelerate](https://github.com/huggingface/accelerate), [bitsandbytes](https://github.com/bitsandbytes-foundation/bitsandbytes). Код `modeling_gfusion.py` официальной закреплённой ревизии просмотрен перед исполнением и скопирован без изменения. Уменьшенная архитектура проверена на CUDA/NF4 только как проверка совместимости библиотек.

## Диалог и выбор формата

Проверяются два прежних коротких промпта: `text-only.txt` и `text-json.txt`. В обоих вход — одинаковый компактный JSON `text`; меняется контракт ответа. Для каждой модели выбор выполняется только по 40 dev-текстам: чистые исправления минус два штрафа за изменённый правильный текст и четыре за сбой структуры, транспорта или завершения. Правило и порядок разрешения равенства записаны до полных dev/test; после просмотра test они не меняются.

В автоматическом API GigaChat первая проба продолжала вымышленный диалог до лимита. Основной запуск использует `render_gigachat20.py`: официальный шаблон токенизатора ревизии `8a6075316cd6d41269f7892caf046f7d5aa274a4` и явный список `additional_special_tokens` из его конфигурации. Запрос отправляется как `raw=true`, без повторного шаблонирования. Для text-json дополнительно используется существующая схема одного строкового поля. Пробные ответы и основные результаты сохраняются отдельно.

```powershell
E:\korrekta\sage-venv\Scripts\python.exe -X utf8 benchmarks/giga20-gfusion/render_gigachat20.py --data benchmarks/cases-v1.jsonl --prompt benchmarks/gigachat-prompts/text-json.txt --output work/gigachat20-cases.jsonl
```

Из `tools/model_benchmark` используйте существующий `bin/benchmark.dart` с `--raw`, `--response-mode text-json`, `--model hf.co/ai-sage/GigaChat-20B-A3B-instruct-v1.5-GGUF:Q4_K_M`, `--endpoint http://127.0.0.1:11435`, соответствующими `--data`, `--prompt`, `--split` и новым `--output`. Для второго dev-варианта замените промпт, подготовленные запросы и режим на `text`.

GFusion запускается из корня проекта:

```powershell
$env:PYTHONPATH = 'E:\korrekta\gfusion-packages;E:\korrekta\sage-transformers4'
E:\korrekta\sage-venv\Scripts\python.exe -X utf8 benchmarks/giga20-gfusion/run_gfusion.py --phase dev
```

Два dev-выхода сравниваются `tools/model_benchmark/bin/compare_texts.dart`. Сохраните сравнение и выполните `select_candidate.py --model gfusion --comparison ПУТЬ --output benchmarks/results/2026-11-03/giga20-gfusion/gfusion-selection.json`. Аналогичный выбор для GigaChat: `--model gigachat20`. Только после сохранения выбора:

```powershell
E:\korrekta\sage-venv\Scripts\python.exe -X utf8 benchmarks/giga20-gfusion/run_gfusion.py --phase test
```

У GFusion сохраняется официальный механизм блочной диффузии: блок 32, до 32 итераций, gamma 0.70, greedy, максимум 768 новых токенов, seed 42. Шаблон диалога официальный; возвращаются только сгенерированные токены, согласно реализации авторов. Исходные строки и декодированное содержимое не нормализуются. JSON разбирается только в выбранном режиме text-json; сбой разбора учитывается отдельно от ответа без ошибок. Первый запрос каждого файла отделён, но модель внутри одного запуска GFusion остаётся загруженной между наборами.

### Кеш общей инструкции

Неизменённый пример авторов повторно обрабатывает весь длинный шаблон для каждого запроса. `prefix_cache.py` сохраняет вычисленные ключи и значения внимания только для общей части всех входов, совпавшей полными блоками по 32 токена. Копия хранится на CPU; для каждого запроса переносится отдельная копия на GPU. Результаты последующих блоков и официальное диффузионное декодирование не подменяются. Исходный `modeling_gfusion.py` не изменён.

Перед dev и test скрипт сравнивает полные последовательности сгенерированных token IDs с кешем и без него на первом примере каждого проверяемого формата. При расхождении останавливается. Подготовка кеша и проверка равенства измеряются отдельно от времени повторных запросов. На dev 4 ноября 2026 года сохранён префикс 1056 токенов (674 758 656 байт на CPU); оба формата дали идентичные token IDs. Первый пример ускорился с 29,8 до 3,8 с для text-only и с 31,8 до 5,2 с для text-json. Это проверка конкретных примеров, а не утверждение о тождественности всех возможных запросов.

## Оценка

Основные наборы: обычный test 160, оформление 120, последний парный holdout 80; дополнительные — раскладка 12 и три абзаца. Все уже использовались при исследовании других моделей. Это внутреннее сравнение, а не новая независимая приёмка.

`compare_texts.dart` использует общий `text-effects-v1`; защищённые фрагменты проверяет `benchmarks/preservation/check_retention.py`. Чистым исправлением считается только точный итог ошибочного текста при успешном контракте и завершении. Отдельно считаются фактические изменения правильных текстов и сбои контракта. Схема JSON не является защитой содержимого имён или оформления. Между моделями память предыдущего движка выгружается; одновременно два движка на GPU не запускаются.

Для завершённого полного прогона из корня проекта:

```powershell
python -X utf8 benchmarks/giga20-gfusion/evaluate.py --model gfusion --dart C:\Users\vostr\code\flutter\bin\dart.bat
```

Для уже сохранённых ответов GigaChat замените `--model` на `gigachat20`. Оценщик проверяет полноту всех пяти наборов, исходники, эталоны и замороженные SHA-256, затем создаёт общие сравнения, проверки protected и компактный overview. Незавершённый JSONL не принимается за полный результат. Готовые оценки можно воспроизвести без запуска моделей; веса и дополнительные библиотеки для этого не требуются.
