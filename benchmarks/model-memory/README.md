# Более экономичная модель при той же связке

Эталон качества сохранён отдельно в [best-known.json](../best-known.json): GigaChat 20B Q4_K_M, общий словарь OpenCorpora/Hunspell, SymSpell, LanguageTool 6.8, выбранный Dart-профиль `inflections`. Пользователь явно попросил запомнить его; дополнительно создана заметка памяти Codex. [Результаты сравнения ресурсов](../results/2026-11-04/model-memory/README.md), [зафиксированные экономичные кандидаты](../resource-profiles.json).

## Что сравнивается

Пять заранее заданных конфигураций: 20B/8192, 10B/8192, 10B/4096, 20B/4096 и 20B/2048. Меньшая модель — официальный [GigaChat3.1-10B-A1.8B-GGUF](https://huggingface.co/ai-sage/GigaChat3.1-10B-A1.8B-GGUF), уже скачанный на E:. Новые веса и зависимости не устанавливались. Для двух моделей используются их собственные официальные шаблоны из локального кеша, а инструкция и схема JSON одинаковы. У 10B шаблон существенно длиннее: максимум 1406 входных токенов против 385 у 20B на этом наборе. Поэтому 10B/2048 не допускает сохранения того же резерва ответа 1024 и не включён в сравнение.

Общий отбор, защита, личный словарь (пустой), словари, версия LT, temperature0/seed42/repeat1 и лимит ответа 1024 неизменны. Применяются существующие Dart-функции `EnsembleRuntime.collect`, `roleFeatures`, `chooseRoles`. Для передачи только что полученного ответа используется аргумент `cachedGiga`; это внутренний перенос текущей генерации, а не повторное использование старых результатов.

Одинаковые **143 знакомых текста**: прежние 140 (60 ошибочных,80 правильных) и три прежних длинных абзаца. Это фиксированное сравнительное измерение, не новая независимая приёмка. Все пять конфигураций получают новые реальные генерации и новые ответы LT, без подбора промпта после оценок. Набор и код зафиксированы коммитом `0aef328` до первого запроса.

До запуска задан рабочий допуск «не критично»: потерять не более 3 чистых исправлений из 60 относительно повторного 20B/8192; не увеличить число изменённых контролей, нарушений protected, лишних эффектов и сбоев; абзацы не должны ухудшиться по чистому результату/лишним эффектам. Уменьшенные контексты 20B проходят,10B — нет из-за дополнительной лишней правки и сбоев. Это выбранный для исследования допуск 5 процентных пунктов, не универсальная граница приемлемого качества.

## Измерение памяти и времени

Отдельный Ollama 0.40.13 на localhost:11435, один загруженный экземпляр модели. Перед конфигурацией модель выгружается. Первый генеративный запрос измеряется отдельно, затем повторяется в основном наборе. Файловый кеш ОС не сбрасывается, поэтому это холодная загрузка модели, а не всей ОС.

Время `seconds` — новый полный тёплый вызов движков: генерация, LT, словари, признаки и выбор. Запись результата исключена, инициализация словарей измерена отдельно. Это ещё не измерение Flutter-интерфейса.

С интервалом примерно 0.5–1 с сохраняются:

- общая занятость GPU через `nvidia-smi` и исходная занятость до загрузки;
- текущий рабочий набор RSS и private bytes семьи собственного Ollama;
- RSS исследовательского Dart-процесса и ранее запущенного LT отдельно;
- оценка размещения модели Ollama и фактический контекст из `/api/ps`.

Пик выборки не равен точному максимуму CUDA. Общая занятость GPU включает рабочий стол и другие приложения. Сумма RSS может повторно учитывать общие страницы; private bytes обозначает обязательства памяти, а не физически занятую RAM. Оценка размещения Ollama тоже не равна RSS. Сравнение не устанавливает минимальные требования к компьютеру.

Одинаковые настройки общего сервера могут привести к разному распределению слоёв по CPU/GPU. Поэтому уменьшение контекста 20B сократило RAM, но не освободило видеопамять: Ollama использовал освободившийся запас для размещения модели. Эффект не следует обещать для другой GPU.

## Воспроизведение

```powershell
& E:/korrekta/sage-venv/Scripts/python.exe -X utf8 benchmarks/model-memory/prepare.py
python -X utf8 benchmarks/model-memory/run.py --phase freeze
& E:/korrekta/sage-venv/Scripts/python.exe -X utf8 benchmarks/model-memory/run.py --phase run --ollama-pid НОМЕР_СВОЕГО_ПРОЦЕССА --lt-pid НОМЕР_LT
python -X utf8 benchmarks/model-memory/evaluate.py
```

Команда freeze не перезаписывает существующий протокол. Повторный эксперимент требует отдельной папки результатов. Для мониторинга используется уже установленный psutil 7.2.2 в среде на E:, без установки пакетов. Все модели и проверяемый текст остаются локальными. Запущенные ранее чужие процессы/модели не останавливаются; исследовательский Ollama имеет отдельный порт и завершается после измерений.

Проверка сохранённых результатов не требует E:, GPU, модели или сторонних Python-пакетов:

```powershell
python -X utf8 benchmarks/model-memory/run.py --phase check
python -X utf8 benchmarks/model-memory/evaluate.py --check
```

Контроль проверяет источник каждого текста, сырые ответы, выбранные индексы, снимки UTF-16, полноту результатов и согласие метрик/пиков с исходными файлами. Неудачные ответы сохраняются и не считаются правильным отсутствием ошибок. Эталонные исправления не передаются в генерацию и прикладной выбор.
