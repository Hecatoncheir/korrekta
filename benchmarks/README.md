# Проверка моделей — M1

Начальный авторский набор русскоязычных примеров для Корректы. Это синтетическая проверка ограниченного охвата, а не независимый языковой рейтинг.

## Порядок

1. Зафиксировать набор, инструкцию и параметры до измерений.
2. Использовать `dev` для проверки инструмента и совместимости; не менять инструкцию после просмотра результатов `test` без новой версии исследования.
3. Для каждой модели выгрузить другие модели, измерить первый запрос отдельно, затем последовательно проверить одинаковый набор.
4. Сохранить сырые ответы, ошибки структуры, отклонённые замены, время и сведения о памяти.
5. Вручную разобрать ложные замечания, пропуски и большие переписывания. Не объявлять модель пригодной только на основании корректного JSON.

В `cases-v1.txt` находятся 200 примеров: 120 с ошибкой и 80 правильных. Из него команда `python benchmarks/prepare_cases.py` в корне проекта воспроизводит входной `cases-v1.jsonl`. Каждая пятая строка внутри категории относится к `dev`: всего 40 примеров для разработки и 160 для отложенной оценки. Инструкция использует отдельные короткие примеры; прямые совпадения с ними исключаются из `test`. Контрольные суммы в протоколе рассчитаны по UTF-8 с переводами строк LF.

Проверяются формы глаголов, согласование, орфография, управление, обязательная пунктуация, правильные конструкции, разговорные фразы, имена и технические термины. Необязательная стилистическая и типографская правка считается лишней. Набор требует дальнейшего расширения и внешней лингвистической проверки.

## Критерии до сравнения

Предварительные ориентиры для проверки по кнопке на текущем компьютере:

- Точность допустимых подсказок не ниже 95%, полнота ожидаемых правок не ниже 70%.
- Не более 5% правильных текстов с ложным замечанием.
- Не менее 99% ответов по схеме; недопустимые или неоднозначные замены всегда отклоняются.
- 95-й процентиль времени повторной проверки короткого абзаца — до 8 секунд. Первый запуск измеряется отдельно.
- При `num_ctx=4096` модель помещается в доступную видеопамять и не мешает работе редактора. Это ориентир для этого компьютера, а не подтверждение минимальных требований для других устройств.

Не достигший порогов вариант не становится моделью по умолчанию. Отдельно оценивается доля правильных исходных текстов, сохранённых полностью, и правильность итогового текста. Маленький набор не подтверждает такой же результат на произвольных пользовательских документах.

## Хранение моделей

Для текущего компьютера используется уже установленное значение `OLLAMA_MODELS=E:\ollama\models`. Веса не включаются в репозиторий. Существующие модели не удаляются.

## Инструмент

Код сравнения на Dart находится в `tools/model_benchmark`. Настольное приложение на этом этапе ещё не создаётся.

Результаты первого прогона и открытые вопросы: [отчёт от 3 ноября 2026 года](results/2026-11-03/README.md). `paragraphs-v1.jsonl` — отдельные пробы длины текста, не дополнительные независимые примеры для оценки качества.

Дополнительно проверена специализированная SAGE 95M через Transformers на GPU и CPU: [запуск](sage/README.md), [результаты и общее сравнение итогового текста](results/2026-11-03/sage/README.md). Исходный протокол Ollama сохранён; метрики разных форматов ответа описаны отдельно.
