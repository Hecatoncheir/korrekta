# Проверка запросов к GigaChat

Сравнение формулировок и форматов ответа для локального `GigaChat3.1-10B-A1.8B Q4_K_M`. Повод — [рекомендации Сбера для онлайн-редактора](https://giga.chat/help/articles/ai-text-editor). Статья советует явно задавать задачу, однако не раскрывает внутренний промпт редактора и не устанавливает тождество онлайн-сервиса и локальных весов. Для Корректы проверяется только минимальная корректура; деловой стиль, сокращение и борьба с тавтологией — отдельные задачи.

## Варианты

- Исходный `benchmarks/prompt-v1.txt`: подробные инструкции, список отдельных правок в JSON, объяснения и примеры.
- [short-edits.txt](short-edits.txt): короткая инструкция с тем же списком правок и объяснениями.
- [text-only.txt](text-only.txt): вернуть только исправленное значение `text`, без объяснений и JSON.
- [text-json.txt](text-json.txt): вернуть исправленный текст в одном JSON-поле, без объяснений.

Для всех вариантов вход одинаков: компактный JSON `{"text":"исходный текст"}` в сообщении пользователя, инструкция в системном сообщении. Изменены и инструкция, и сложность формата ответа; опыт не изолирует причинный вклад каждого фактора. Полный результат не обрезается и не нормализуется: лишнее вступление, новая строка, кавычки-обёртки или пояснение ухудшают оценку.

## Зафиксированный порядок

1. Подготовить четыре запроса, новый набор и [контрольные суммы](checksums-v1.json) до новых обращений к модели.
2. Проверить три новых варианта на прежних 40 `dev`-примерах. Старый dev-прогон используется как сохранённая точка сравнения.
3. Выбрать вариант только по dev, по правилу из [protocol-v1.json](protocol-v1.json): чистые исправления минус штрафы за изменённые правильные тексты и сбои контракта. Вариант, который ничего не исправляет, не получает положительных баллов.
4. Сохранить выбор, затем проверить выбранный и исходный запросы на новом `holdout-v1.jsonl` из 80 текстов. Промпты после просмотра holdout не менять.
5. Выбранный вариант дополнительно проверить на прежних test 160 и preservation 120 как диагностических наборах.

Новый набор — 40 авторских контекстов в двух вариантах, а не 80 независимых контекстов. По десять пар обычных фраз, имён/кавычек, эмодзи/оформления и технических строк. Точных совпадений с прежними двумя наборами нет. Защищённые фрагменты не затрагиваются эталонной ошибкой. Это внутренний отложенный опыт, не внешняя независимая лингвистическая приёмка.

`python -X utf8 benchmarks/gigachat-prompts/prepare_holdout.py` воспроизводит набор и проверяет замороженные SHA-256 по UTF-8/LF. Изменение промптов требует новой версии исследования.

## Запуск

Используется прежний Ollama 0.40.13 и уже скачанные веса на E:, отдельный локальный сервер `127.0.0.1:11435`, облако отключено. Параметры неизменны: temperature 0, seed 42, context 4096, predict 768, repeat penalty 1, think false. Новые модели не скачиваются.

Из `tools/model_benchmark`:

```powershell
dart run bin/benchmark.dart --model hf.co/ai-sage/GigaChat3.1-10B-A1.8B-GGUF:Q4_K_M --endpoint http://127.0.0.1:11435 --data ../../benchmarks/cases-v1.jsonl --split dev --prompt ../../benchmarks/gigachat-prompts/text-only.txt --response-mode text --output ../../work/prompt-text-dev.jsonl
```

Для других вариантов задайте соответствующий файл и `--response-mode edits` или `--response-mode text-json`. По умолчанию сохраняется прежний режим `edits`. Команда записывает инструкцию, формат, модель, параметры, полный ответ и итоговый текст, ошибки контракта и время. `--response-mode text` не задаёт грамматику JSON в запросе к Ollama. `text-json` ограничивает ответ схемой одного строкового поля.

Результаты сравниваются через `compare_texts.dart`. Выбор по dev воспроизводит `select_candidate.py --comparison ФАЙЛ --output ФАЙЛ`. Пути внутри сравнения разрешаются относительно `tools/model_benchmark`, как при исходном запуске. Выбор по test скрипт отклоняет. Существующий файл выбора не перезаписывается.

Метрики `precision` в старой итоговой записи `summary` используют разные единицы: отдельные предложения для `edits` и весь изменённый текст для текстовых режимов. Их нельзя напрямую сравнивать. Общие метрики — `text-effects-v1`, число полностью правильных исправлений и изменения контрольных текстов. Сбои структуры, транспорта или остановка по лимиту считаются отдельно; такой ответ не получает чистое исправление даже при сохранении исходного текста.

Для применения в приложении текстовый ответ ещё нужно превратить в локальные правки на Dart и проверить защищённые диапазоны и версию исходника. Отдельная генерация объяснений после проверки правок здесь не реализована и не измерялась. [Результаты](../results/2026-11-03/gigachat-prompts/README.md).
